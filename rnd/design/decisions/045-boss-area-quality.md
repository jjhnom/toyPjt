# 045. 보스 장판 공통 품질 및 렌더링 기준

후속 [046 정체성 분리](046-poison-binding-identities.md)에서 독·암흑 구속을 분리해 6팔레트로, [047 참고 아틀라스 반영](047-reference-boss-effects.md)에서 요청 스킬을 분리해 8팔레트로 확장했다. 아래 메모리 수치는 이 문서 작성 시점의 초기 5팔레트 기준이다. 캐시·해상도·필터 기준은 계속 적용한다.

## 문제와 조사 결과

기존 지속 장판은 원본 96×96의 바닥 타원 하단 6~14px를 원형으로 늘려 사용했다. 예를 들어 독 장판은 하단 7px를 실제 반경 75px에 대응시켜 세로 약 10.7배 확대했고, 빙결은 하단 14px를 반경 85px에 대응시켰다. 최근 용암·마왕 충격파도 원본 64px의 유효 지름 60px를 130~160px로 확대했다. 단순히 전체 PNG를 2배로 저장해도 원본 정보와 확대 흔적은 개선되지 않는다.

설치된 Phaser 소스를 확인하면 `setFilter(0)`은 LINEAR다. 기존 캐시 중에도 이미 LINEAR를 쓰는 것이 있으므로 필터 변경만으로 해결할 수 없었다. `pixelArt: true`는 기본 텍스처 설정과 최종 canvas의 인라인 `image-rendering: pixelated`에도 영향을 준다. CSS 규칙만 바꾸면 인라인 스타일에 가려지는 점도 실제 브라우저에서 확인했다.

## 공통 기준

| 요소 | 기준 |
| --- | --- |
| 원본 재질 | 192×192 전용 프레임. 작은 타원/스프라이트의 업스케일을 원본 제작으로 간주하지 않음 |
| 확대 한도 | 현재 최대 지름 210px 기준 1.1배 이하. 새 보스가 넘으면 256/384px 등으로 원본을 새로 제작 |
| 재질 필터 | Phaser LINEAR=0, 실제 WebGL MAG_FILTER=9729 확인 |
| 캐릭터 필터 | 기존 NEAREST 유지, 실제 WebGL MAG_FILTER=9728 확인 |
| 판정 경계 | attack.radius를 직접 사용하는 별도 world-space Graphics. 선 외곽을 반경 안에 배치 |
| 중심·표시 크기 | origin=(0.5,0.5), position=(attack.x,attack.y), 표시 지름=2×attack.radius |
| 내부 재질 | 부드러운 방사형 농도, 얇은 균열/서리 결정/독 기포, 낮은 대비의 내부 흐름 |
| 입자·잔상 | 독립된 투명 이미지층. 작은 빛·기포·분진 위주이며 캐릭터 중심을 과도하게 가리지 않음 |
| 아틀라스 | 프레임 사이 4px, 가장자리 투명 여백. 한 변 1024px 이하 |
| 수명·배속 | 기존 hazard age 사용, 독립 피해/타이머 추가 금지, 시크 결정성 유지 |
| 재사용 | hazard 슬롯당 이미지 2개와 재사용 Graphics 1개. Graphics 최대 32개 |

`pixelArt: true`, `roundPixels: true`와 720×1280 논리 해상도는 유지한다. 최종 canvas CSS 축소는 `auto !important`로 인라인 pixelated를 덮는다. 캐릭터의 GPU 원본 샘플링은 계속 NEAREST다. 하나의 canvas를 최종 합성한 뒤에는 CSS 보간을 캐릭터/장판별로 나눌 수 없으므로 이 마지막 축소 단계는 공통이다. WebGL 텍스처 샘플링은 개별 설정으로 분리한다. Canvas 2D 전용 환경과 실제 Android 기기는 별도 확인 대상이다.

## 구현

`src/ui/bossAreaQuality.ts`가 흙·독·빙결·용암·암흑 5팔레트의 192px 재질과 입자 프레임을 벡터 경로·그라디언트로 직접 생성한다. 원본 저해상도 이미지를 확대하지 않는다. 생성은 텍스처 관리자당 한 번만 실행하며 게임 프레임 중 rasterization/readback을 하지 않는다. 낙하의 마지막 150ms, 확산 40~190ms, 용암·마왕 비피해 잔상 650ms 등 기존에 정한 연출 시계는 유지한다.

`BossVfxController`는 고품질 재질 → 경계 Graphics → 입자의 세 층을 재사용한다. 완성된 HD 캐시가 모두 있으면 사용하지 않는 구형 장판 캐시는 생성하지 않는다. HD 생성 실패 시 기존 시각 경로를 유지하고 피해 처리에는 영향을 주지 않는다.

5개 HD 아틀라스의 RGBA 기본 데이터는 13,522,432bytes(약 12.9MiB)다. 이 값은 크기로 계산한 기본 데이터이며 드라이버 메모리나 실측 힙 값이 아니다. 픽셀 원본·캐릭터 이미지는 보존하고 전투 판정·방 진행·저장 로직을 변경하지 않는다.

## 검증 기준과 자료

- 5보스·9개 원형 스킬 × 3페이즈 × 4배속의 108조합에서 공격 계획과 피해 콜백을 수정 전과 비교한다.
- 실제 192px 원본·지름·중심·마스크, 장판 LINEAR/캐릭터 NEAREST 및 최종 CSS를 읽어 확인한다.
- 20회 시크 후 객체 수가 같고 활성 이펙트·경계 Graphics가 남지 않아야 한다.
- 모바일 360/390 너비와 실제 GameScene을 확인한다. Android 실기기 FPS·메모리는 별도 실측한다.

비교 이미지와 실제 원본 프레임은 `artifacts/boss-area-quality-20261113/`에 보관한다. 현재 품질 검사 기준은 `tests/boss-area-quality-browser.mjs`다. 이전 작업의 특정 아틀라스에 고정된 before/after 자료는 해당 작업 시점의 기록이며, 새 품질 검증은 이 공통 기준을 따른다.
