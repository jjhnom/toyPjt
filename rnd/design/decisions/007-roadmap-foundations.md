# 로드맵 0~1단계 — 경제 측정과 룸 체크포인트

상태: 0~1단계 구현 및 모델·브라우저 검증 완료. 사용자 요청: 2026-11-06 “개선 로드맵 확인해서 단계별로 진행”. 후속 킬 보상 정책은 `008-kill-reward-curve.md`에서 선택한다.

## 범위와 순서

로드맵의 기존 수입·효율 수치를 정답으로 고정하지 않는다. 0단계에서 기존 55개 테스트/빌드 기준을 재실행하고 실제 거래 로그, 동일 시드 경제 시뮬레이션과 최소 제작 비용 리포트를 만든다. 1단계는 로드맵의 권장 저장 정책을 구현한다. 게임 수치 변경·신규 영웅·유물·무한 진행은 후속 단계다.

## 0단계: 경제 측정

- 킬/방/보스/소환진/판매, 유료·무료 소환/일반 조합/승급/간편 제작을 원천 거래에서 기록한다. 실패 거래는 기록하지 않는다.
- 재화와 소환권을 별도로 집계한다. 초기 자금은 수입으로 세지 않는다. 스테이지·방·보유/출전 수와 단계 시작/보스 처치 시 편성·★ 스냅샷을 남긴다.
- 메모리에는 최근 512건만 보유하며 누적 합계는 유지한다. 저장을 불러오면 그 시점부터 새 관측 구간을 시작한다. 외부 전송이나 영구 로그 저장은 없다.
- `npm run economy:report -- 42`는 같은 시드의 모든 방/최단 보스 경로에 현재/배율 제거/제곱근 배율을 적용한다. 실제 게임의 배율은 변경하지 않는다.
- 모델은 필수 적을 모두 처치한다고 가정한다. 보스 호위도 보스보다 먼저 처치한다. 전투 시간 의존 추가 소환·사망·실제 DPS·생존·오버힐·이동 시간은 측정하지 않는다. 1스테이지당 고정 목표 1기를 자금이 되는 첫 클리어에서 간편 제작한다.
- 제작 비용은 기존 `quickCraftPlans`와 같은 조건/티어 잠금/경로를 사용한다. 명목 단일 대상 DPS는 효율 순위나 실측 전투력으로 취급하지 않는다.

## 1단계: 저장 정책

- 스테이지 시작 저장을 유지하고 방 보상 확정 직후, 정비 거래 성공 직후 및 정비 종료에 저장한다. 전투 중에는 쓰지 않는다.
- v1 스테이지 시작 저장과 옛 `SHOP` 라벨을 계속 읽고 다음 정상 저장부터 v2로 쓴다. 기존 데이터에 보상·회복을 추가하지 않는다.
- v2는 런 ID, 단계(스테이지 시작/방 클리어/중간 보스 클리어), 현재 방, 격자·일회성 선택, 보유/배치/자금/소환권, 본체 HP, 출전 개체 HP·부활/회복/주요 스킬 남은 시간을 보존한다.
- 쓰러진 유닛은 로드만으로 부활하지 않는다. 오프라인 동안 부활 시간을 차감하지 않는다. 다음 방 부활 규칙은 현행 그대로 둔다.
- 중간 보스 보상은 저장에 포함하고 이어하기 시 정비를 다시 열어 다음 스테이지 전환만 수행한다. 최종 승리/패배/새 게임은 저장을 종료한다.
- 하나의 키 교체로 원자적으로 기록하고 직전 정상본을 별도 키에 보존한다. 최신본 손상 시 이전 정상본으로 복구했다는 안내를 표시한다. 저장 실패 시 경고하고 마지막 정상본을 유지한다.
- 미출시 성장 필드·무한 스테이지는 허용하지 않는다. 새 의존성, Android 설정 변경은 없다.

## 수용 기준

1. 현행 스테이지별 킬/방 보상·필수 스폰·제작 가격이 회귀 없이 유지된다.
2. 거래 로그 합계와 실제 잔액/소환권이 일치하며 같은 시드/정책은 재현된다.
3. v1 호환, v2 각 단계, 손상/저장 실패/종료, 일회성 보상·판매/소모 유닛 복원 방지, 부활 타이머를 검증한다.
4. 실제 Phaser 브라우저에서 재개·정비·이벤트·보스 전환을 확인하고 자동 테스트와 빌드를 실행한다.

위험: 시뮬레이터는 인간 플레이 경제를 대신하지 않는다. 저장 실패 뒤 강제 종료하면 최근 변경이 유실될 수 있다. Android 실기기 중단/복귀 검증은 별도다. 롤백 시 v2를 읽지 못하는 구버전은 이어하기를 제공할 수 없으므로 코드와 저장 버전 변경을 함께 되돌려야 한다.
