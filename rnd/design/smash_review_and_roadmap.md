# 소환사의 원정 — 코드 리뷰 및 단계별 개선 로드맵 (개정판)

> 상태: **설계 / 구현 대기** · 기준 저장소: `jjhnom/toyPjt/rnd` · 개정: 2026-11-05  
> 원본: 사용자가 제공한 `smash_review_and_roadmap.md`의 발견 사항 및 제안을 재구성했다.  
> **주의:** 본 문서의 개선 제안은 구현 완료를 뜻하지 않는다. 아래 수치 중 플레이 실측으로 검증하지 않은 값은 모두 **가설·설계 목표**다.

## 0. 목적과 변경 원칙

소환 → 재료 확보 → 조합 → 출전 편성 → 룸 전투라는 기존 게임의 핵심 루프를 유지하면서, (1) 경제·유닛 밸런스를 검증 가능하게 만들고, (2) 중단·재시작 안정성을 올리고, (3) 영웅/유물/무한 모드 성장 축을 단계적으로 도입한다.

- 범위: `rnd/`의 게임 시스템과 디자인 결정. 별도 반영된 유닛 22종 및 5개 스테이지 로스터 전체 재설계는 제외한다.
- 원칙: **코드/테스트로 확인한 사실**, **원본 리뷰의 계산 또는 가설**, **아직 승인되지 않은 설계**를 구분한다.
- 우선순위: 데이터 손실 예방 → 경제 측정 → 작은 수치 조정 → 신규 시스템.
- 진행 방식: 핵심 규칙·밸런스 변경은 `AGENTS.md` 지침에 따라 `design/decisions/`에 선택지와 근거를 기록하고 사용자 승인 후 구현한다. Git push/merge, 새 의존성, 서명 변경도 별도로 검토한다.
- 검증 범위: 문서 수정은 경로·계약·용어 일관성을 검토한다. 실제 코드 변경 시 `npm test`, `npm run build`, 입력 변경 시 `node tests/browser-smoke.mjs` 및 필요한 실기기 검증을 수행한다.

### 경제/밸런스 측정 시 반드시 구분할 값

- **유입:** 킬, 룸 클리어, 보스/정예, 이벤트 보상, 환급.
- **유출:** 소환, 조합 추가 비용, 승급, 강화, 회복/서비스.
- **잔액:** 스테이지 시작/종료 시점, 분대 보유 수·등급·출전 수.
- **전투:** 처리 DPS(실제 명중 포함), 생존 시간, 타깃 선택, 오버킬/오버힐, 관통/연쇄 실효 횟수.
- 원본의 스테이지별 예상 수입(약 640/1350/3350/6580/11230)과 유닛 효율(예: 별빛 명궁 6.1)은 **기준 가설**로만 둔다. 실제 데이터가 없는데 목표 테스트의 정답으로 고정하지 않는다.
- 티어별 비용 순서가 절대적으로 단조 증가해야 하는 것은 아니다. 조건 조합·지원 가치·재료 수급 난도를 고려한 **설계상 예외를 허용**한다.

## 3. 설계 규칙 — 시스템 간 충돌 방지

### 3.1 용어와 인덱스

- UI 표시 스테이지 `S = internalIndex + 1`. 내부 `STAGES[4]`는 5스테이지이다.
- 무한 첫 스테이지는 UI **6스테이지**, 내부 `index = 5`. 무한 진행 번호 `m = index - 4`이면 첫 무한은 `m = 1`.
- 내부 인덱스/화면 표기/저장 데이터 인덱스를 하나의 정의로 고정하고 모든 공식·테스트에 예제를 적는다.
- 유닛 *보유 한도*와 *출전 한도*는 독립 계약이다. 확장 시 UI 및 저장 검증도 함께 변경한다.

### 3.2 효과 계산 파이프라인

`base → additive(동일 그룹 내 합연산) → multiplicative(명시적으로 지정된 서로 다른 그룹) → cap → final` 순서를 통일한다.

- 적용 대상: 영웅/분대 공격력, 공격 속도, 이동 속도, 체력, 회복, 받는 피해, 조합 비용, 킬 보상.
- 재능·유물·강화소가 동일 스탯에 작용할 때 중복 집계하지 않도록 **효과 ID와 소스**를 보존한다.
- 할인/공속/받는 피해 감소는 **최종 상한**을 둔다. 예: 공격 속도 배율 최대 2.5배, 조합 비용 할인 최대 40%, 피해 감소 최대 50%는 **승인 전 제안값**.
- 부활/회복은 최대 HP와 현재 HP의 동시 갱신 규칙을 정의한다. 최대 HP 증가만으로 즉시 풀 회복되지 않도록 한다.
- '무한 레벨'과 '무제한 효율'은 다르다. 매 레벨 +1%를 곱연산하면 기하급수적으로 증가하므로 **체감 증가/총상한**과 모순이다. 초월 성장에는 총상한 또는 로그/감쇠 공식을 명시해야 한다.

### 3.3 수입 정책과 강화 비용

- 킬 보상 후보: (A) 스테이지 보상 배율 미적용, (B) `sqrt(rewardMult)` 적용. 한 가지를 실측/시뮬레이션으로 비교해 결정한다.
- `cost(level) = ceil(base * 1.35 ** level)`은 강화 **현재 레벨→다음 레벨** 비용으로 정의한다. 소수점 반올림 방식을 고정한다.
- 무한 강화는 숫자상 레벨 상한이 없어도 자원/정수 오버플로·저장 크기·실제 스탯 상한이 생기므로 수치 안전성 테스트가 필요하다.
- 스테이지 5 종료 강화 총레벨 '25~35'는 실측 기반 지표가 아니라 검증할 **초기 목표안**이다.

## 4. 기능 설계(초기 MVP / 후속)

### 4.1 체크포인트 v2 — 신규 콘텐츠보다 먼저

**저장 시점:** 기존 스테이지 시작 체크포인트 유지 + 룸 클리어 후 보상/정비를 확정하고 다음 전투 진입 전에 저장. **전투 중 저장하지 않는다.**

필수 필드(개념적 스키마):

| 범주 | 포함 데이터 | 검증 포인트 |
| --- | --- | --- |
| 공통 | `schemaVersion: 2`, `runId`, `stageIndex`, `checkpointPhase` | 지원 가능한 버전·상태만 수락 |
| 진행 | 격자/룸 IDs, 현재 룸, 방문/클리어 룸, 보스·이벤트 결정 상태 | 연결성, 인덱스 범위, 중복 보상 금지 |
| 경제 | 재화, 소환권, 분대 목록·배치·별/체력 | 유닛 ID·제한·유효 수치·고유 ID 검사 |
| 성장(후속 필드) | 영웅 클래스/레벨/XP/재능, 유물, 강화, 변이 | 미출시 기능은 기본값으로 마이그레이션 |
| 안전 | 저장 세대/트랜잭션 ID, 무결성 점검 정보(선택) | 중간 종료 및 반복 저장 대응 |

- v1 → v2: 기존 '스테이지 시작' 데이터는 해당 스테이지 시작 상태로 복원하는 **무손실 호환**을 우선한다. 새 필드는 기본값을 채운다.
- 잘못된 v2를 임의 추정으로 복구하지 않는다. 이전 정상 체크포인트가 있으면 안내 후 사용하고 없으면 안전한 새 런 안내를 제공한다.
- 보스 클리어/보상 선택/저장 중 앱 종료 시 **보상 중복 지급**과 **이미 소비한 재료 복원**이 없는지 테스트한다.
- 영구 숙련도·설정은 별도 저장 키와 스키마를 사용한다. 런을 지워도 영구 데이터가 삭제되지 않는다.
- 무한 진행을 v2 첫 릴리스에 강제하지 않는다. `stageIndex >= STAGES.length` 허용은 무한 생성기 릴리스 때 명시적으로 켠다.

### 4.2 경제·조합

1. 동일 시드/동일 플레이 경로에서 스테이지별 재화 흐름 로그를 만든다.
2. 레시피 비용은 **최저 조달 경로별 재료 비용 + 추가 비용 + 점유 슬롯/위험 비용**으로 비교한다. 조건 레시피는 가능한 입력 조합을 열거한다.
3. 황혼 대마법사·별빛 명궁·성기사 등은 지표와 역할을 검증한 뒤 한 번에 소수만 조정한다.
4. 지원 유닛은 본체 전용/분대 전용/혼합 중 목표를 정한다. 퍼센트 회복은 최대 HP 증가와 조합될 때 지나치게 강해질 수 있으므로 대상 수·횟수·쿨다운을 함께 제한한다.
5. 자동 테스트는 **불변식**(음수 재화 없음, 재료 중복 소비 없음, 한도 준수)을 실패로 처리하고, **밸런스 지표**(DPS, 효율, 순서)는 승인 전 경고 리포트로 둔다.

### 4.3 유물 MVP

- 1차 범위: 유물 3종(분대 공격력, 소규모 회복, 조합 할인), 선택 UI 1개, 런 저장/복원.
- 중복 유물 획득, 선택 취소, 인벤토리 상한, 적용 순서와 같은 계약을 먼저 정한다.
- 기존 소환진 및 정예/보스의 보상 로직을 동시에 전부 변경하지 말고 **한 획득처만 연결**해 검증한 뒤 확장한다.
- 후속: 속성 인장, 재료 보존, ★승급 재료 감소, 희귀도/리롤, 사이드 유물 방.

### 4.4 영웅 MVP

- **1종부터:** 견습 소환사, 이동 중 자동 공격, 기본 레벨/XP/체력, HUD. 초기에는 액티브 버튼·3장 재능 카드·숙련도·장비를 제외한다.
- 영웅 무기는 기존 유닛 사격 스타일을 재사용하되, **피해 원천 ID**와 킬 통계를 유닛과 구분한다. 타입 계약을 확인하고 구현한다.
- 지휘관 정체성: 분대가 주력이다. '영웅 DPS ≤ 전체 분대 DPS의 30%'는 특정 테스트 구성에서 점검할 **가이드라인**이며 모든 편성/0유닛 상황에서 강제하는 런타임 규칙이 아니다.
- 성장: `xpToNext(level) = floor(40 * 1.18 ** (level - 1))`은 초안. XP 획득/처치 귀속/레벨업 중 복수 레벨 상승/일시정지/저장 복원을 함께 정의한다.
- 후속: 액티브 스킬 버튼 1개, 3레벨마다 3지선다 재능, 기사·원소 술사, 숙련도. UI 버튼은 조이스틱·모달·터치 취소 및 화면 크기 변화를 테스트한다.

### 4.5 무한 모드 MVP

- 5스테이지 최종 보스 후 **[승리 종료] / [무한 모드 계속]**을 제시한다. 버튼 중복 선택·앱 재진입에도 결과가 한 번만 확정되도록 **선택 상태를 저장**한다.
- 무한 첫 내부 인덱스는 `5`, UI 표시 6스테이지. `generateEndlessStage(index)`가 고정 5종 테마와 보스를 순환시킨다.
- 기준(제안): 5×5 맵·15개 룸, 정예 `min(4 + floor((index - 5) / 2), 6)`. 생성기 검증은 방 수/연결성/보스 접근성/보상 중복 없음.
- 적 HP 확장안: `hpMult(index) = hpMult(4) * 1.15 ** (index - 4)` (index ≥5); 피해는 `damageMult(4) * (1 + 0.15 * (index - 4))`. 기존 1~5 스케일링 값 변경과 별도 승인한다.
- 속도 `min(1.3 + 0.01 * (index - 4), 1.45)`, 활성 적 `<=64`, 스폰 간격은 **기존 함수 값의 하한이 0.6배**라는 의미인지 **절대 시간 0.6초**인지 구분하고 실제 스폰식과 맞춘다.
- 보상 증가율 `1.06 ** m`은 **추가 무한 배율**로만 정의하고 적 수/룸 보상과 결합한 전체 수입 상한이라고 단정하지 않는다.
- 우선 구현: 이어하기/스테이지 생성/기초 확장/최고 기록. 변이 선택·각성 보스·정예 접두사는 안정화 후 도입한다.
- 무한 모드는 적 HP가 늘어난다는 이유만으로 종료가 보장되지 않는다. 게임 오버 외에 `max safe stage`, 수치 상한, 종료 UI를 명시한다.

### 4.6 원정 강화 / 각성 / 영구 성장

| 시기 | 초기 대상 | 주의점 |
| --- | --- | --- |
| 강화소 1차 | 분대 공격/공속/체력, 영웅 공격/체력, 방어 | 효과 적용 중앙화와 저장 검증 선행 |
| 강화소 2차 | 조합 할인, 보유 +6(최대 22), 출전 +2(최대 8) | 편성 UI·AI·성능에 영향. 제한 증가는 별도 승인 |
| 유닛 각성 | ★3 개체당 각성 1~10 | 조합/판매 시 각성 소멸 경고, 개체 ID 기반 저장 |
| 서비스 | 분대 완치, 즉시 부활, 리롤 | 룸 이동·부활 타이머와 충돌 방지 |
| 영구 성장 | 영혼 조각, 숙련도, 도감 | 런 데이터 분리, 실패/재시도 시 **보상 중복 방지** |

영구 보너스는 '무한 레벨 + 총보너스 상한'을 병용할 경우, 상한 도달 후 구매 효용을 별도로 정의해야 한다. 가격만 계속 증가하고 효과가 0인 구매는 허용하지 않는 쪽을 권장한다. 영혼 조각 지급 공식도 출시 전 루프 길이와 실패 보상 비율을 실측해 결정한다.

### 4.7 보스 / 탐험 / UX / 성능

- 보스: `bossId`를 렌더링·행동·패턴 파라미터 데이터에 실제 연결, 보스별 최소 한 가지 회피 학습 포인트, 예고 가시성 검증.
- 탐험: 사이드 룸 전용 선택 보상 한 종류를 먼저 시험, 미니맵의 정보 공개량 및 경로 다양성 측정.
- UX: 튜토리얼, 도감, 볼륨·진동, 피해 숫자 토글, 시너지 미리보기, 종료 통계. 색상만으로 속성을 구별하지 않도록 아이콘 병행.
- 성능: 스테이지 5 고부하 조건(적 60~80, 탄환 150)은 **테스트 목표 시나리오**로 두고, 실기기에서 기종·OS·해상도·관찰 시간·FPS/프레임타임·메모리 수집. 병목 확인 전 충돌 시스템 교체나 에셋 대량 변환은 하지 않는다.
- 릴리스: `capacitor.config.json`의 자리표시자 appId, Android 서명/패키지 ID 변경은 출시 준비 승인 후 실시.

## 6. 각 PR의 표준 완료 조건(Definition of Done)

1. 변경의 **현재 동작 / 목표 동작 / 비범위**가 PR 설명에 있다.
2. 규칙 변경은 `design/decisions/` 결정 문서와 사용자 승인 사항을 연결한다.
3. 신규 저장 필드가 있다면 구버전 마이그레이션과 부정 데이터 검증을 포함한다.
4. 경제 거래는 재화 음수·중복 소비·중복 지급이 없으며, 모달/씬 재시작 상황을 테스트한다.
5. `npm test` 및 `npm run build` 결과를 기록한다. 미실행이면 이유를 적는다.
6. 입력 변경은 `tests/browser-smoke.mjs` 조건 및 실기기 테스트 가능 여부를 기록한다.
7. 게임 성능 관련 주장은 기기/시나리오/FPS 또는 프레임타임과 함께 제시한다.
8. 위험, 롤백 방안, 수정 파일, 다음 단계가 리뷰에 포함된다.

## 7. 승인할 핵심 의사결정(우선순위 순)

1. **저장 정책:** 룸 클리어/정비 완료 직후 저장을 허용할지, v1 시작점 복원을 보존할지.
2. **경제 정책:** 킬 보상 배율을 없앨지 / 제곱근으로 낮출지 / 현행 유지할지.
3. **지원 역할:** 영웅 보조 / 분대 회복 / 혼합 중 주 역할.
4. **부활 규칙:** 방 이동 자동 부활을 계속 허용할지, 비용·지연을 둘지.
5. **영웅 조작:** 첫 릴리스 자동 공격만, 후속 액티브 버튼 추가(권장) 여부.
6. **확장 범위:** 영웅 MVP(1종) → 유물 MVP(3종) → 무한 모드 MVP 순서 승인 여부.
7. **메타 성장:** 영혼 조각/숙련도는 검증 후 도입할지.
8. **목표 세션:** 한 판 플레이 시간, 목표 난이도, Android 최소 사양.
