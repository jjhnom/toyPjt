# 소환사의 원정 — 참고 영상 기반 디자인 적용 가이드 (Phaser 3)

> 기준: `jjhnom/toyPjt` 저장소 `main/rnd`. 2026-11-07 확인한 README, AGENTS.md, game-brief.md, fantasyTheme.ts 및 src 폴더 구조 기준. 본 문서는 디자인 제안이며 구현 완료를 의미하지 않습니다.

## 1. 프로젝트 정체성과 유지할 요소
- 게임: **소환사의 원정**. Phaser 3 + TypeScript + Vite + Capacitor Android.
- 핵심 플레이 루프: 전투 → 재화 → 지정 소환 → 레시피 조합 → 출전 편성 → 다음 방 전투.
- 22종 유닛, 5개 스테이지, 중간 보스와 최종 보스, 스테이지 시작 체크포인트를 보존.
- 참고 영상의 *전투 가독성, 강렬한 속성 이펙트, 계층적 UI, 보상 강조*를 활용하되 게임 규칙·원본 자산을 복제하지 않음.

## 2. 화면별 UX/비주얼 제안
### A. 전투 `src/scenes/GameScene.ts`
- 상단 12~16%: 스테이지/방, 적 진행도, 재화 등 핵심 정보. 배경보다 명도 높은 텍스트와 어두운 반투명 패널.
- 중간 65~72%: 캐릭터/몬스터 실루엣 확보. 적·아군·투사체 색상 충돌 방지.
- 하단 16~22%: 조작 힌트와 중요 액션만 유지. 손가락 가림 영역과 안전 영역 확보.
- 보스 등장 시 화면 상단 보스 HP, 진입 경고 0.8초, 패턴별 색상 신호를 제공.
- 피격은 짧은 플래시와 적은 카메라 흔들림으로, 보상은 반짝임+흡수 궤적으로 차별화.

### B. 정비/편성 `src/scenes/SquadScene.ts`
- 동료 카드의 역할(전열/후열), 속성, 희귀도, 체력, 조합 재료를 동일한 서식으로 표시.
- '현재 보유 → 조합에 사용 → 편성 결과' 흐름을 시각적 선으로 연결.
- 가능한 조합은 시각적으로 강조, 재료 부족 상태는 원인과 수량을 표시.
- 중요 버튼(소환/조합/다음 방)의 위계를 통일하고 비활성 이유를 텍스트로 설명.
- 기존 SquadScene을 주 정비 흐름으로 유지하며 RewardScene 중심 구조로 변경하지 않음.

### C. 타이틀 `src/scenes/MenuScene.ts`
- 로고 → 진행 상태(이어하기) → 새 모험의 순서로 계층 구성.
- 캐릭터 픽셀 아트를 주인공으로, 명확한 클릭 영역과 안정적인 대비 제공.

### D. 결과 `src/scenes/GameOverScene.ts`
- 승리/패배의 감정 차별화, 획득 재화·진행 거리·기여 유닛을 구분해 요약.

## 4. 이펙트 규칙 `src/ui/skillEffectTextures.ts`
- **기본 공격:** 0.10~0.20초 작은 섬광 + 투사체의 약한 잔상.
- **강화 공격:** 0.25~0.40초 부채꼴 스윕/파티클 + 충격 링.
- **궁극기급 공격:** 예고 0.25초 → 발동 0.30초 → 잔광 0.35초. 광원/화면 흔들림은 강도 설정 가능하게.
- **빙결:** 시안 코어, 작은 흰 파편, 짧은 잔광.
- **화염:** 오렌지 중심, 어두운 적색 테두리, 스파크.
- **번개:** 불규칙 꺾임, 1~2회 추가 플래시, 흰색 코어.
- **마법/비전:** 보라색 궤적, 회전 문양, 반짝이는 파편.
- 중요한 적 공격 전조 색은 플레이어 스킬의 효과 색과 최대한 분리.
- 모바일에서 최대 동시 파티클 수 상한을 두고 저사양 기기에서 자동 축소.

## 5. Phaser 구현 가이드
1. `src/ui/fantasyTheme.ts`의 `FANTASY`, `paintPanel`, `fantasyButton`, `pixelPanel`을 디자인 시스템의 단일 진입점으로 유지.
2. 신규 테마 요소는 기존 함수를 확장하는 방식으로 구현하고, 씬별 임의 색상 상수 중복을 피함.
3. 효과는 `src/ui/skillEffectTextures.ts`에서 텍스처 재사용·풀링 방식 우선.
4. 픽셀 아트는 일관된 기준 스케일 및 `NEAREST` 렌더링을 사용하고, 텍스트는 가독성 기준으로 별도 처리.
5. Capacitor Android의 안전 영역, 세로 화면, 터치 영역, 해상도 비율을 확인.
6. 게임 규칙, 스테이지·유닛 밸런스 및 저장 정책은 디자인 작업으로 임의 변경하지 않음.
