# Skill: Smash Roguelike Mechanics (Phaser 3 Engine)

## Overview
사용자가 설명한 스타크래프트 '스매쉬(Smash)' 유즈맵의 **유닛 소환과 조합**을 중심으로 모바일 게임을 설계한다. 목표 루프는 **[전투로 재화 획득 → 유닛 소환 → 재료 유닛 확보 → 조합으로 새 유닛 생성 → 분대 구성 → 다음 방 전투]**다. 격자형 룸은 프로젝트의 진행 장치이며 원작의 정확한 규칙으로 단정하지 않는다.

현재 구현은 스토리 5개 스테이지와 S6~1000 무한 원정, 지정 소환·고정/조건 조합·★ 승급·판매·보유/출전 관리와 독립 이동/사격을 제공한다. 개별 유닛 체력·전열 어그로·전투 불능·부활·지원 회복과 편성 시너지3종·발견 도감·3클래스·영혼 조각 영구 성장2종을 구현했다. 무작위 소환·속성 상성 매트릭스는 미구현이다. 화상 오라·암살 처치 시 쿨다운·드루이드 공격 보조·불사조 부활 연계·수호신 방어막은 현재 코드에 구현되어 있으며, 2026-11-05 자동 테스트와 실제 Phaser 브라우저 검증으로 확인했다. 수치는 `src/config/skillData.ts`, 적용 경로는 `PlayerSquad`·`GameScene`·`BurnComponent`를 따른다. 원작의 소환 확률·조합표는 확인되지 않았으므로 프로젝트 설정과 구분한다.

독·분열·추적은 가시 수호자의 중독, 폭풍 궁수의 최초 적중 분열, 번개 정령의 최초 표적 추적으로 구현했다. 수치·중첩·분열 제한·적 풀 재사용 처리와 밸런스 가정은 [스킬 결정 기록](../../design/decisions/003-projectile-skills.md)을 따른다.

공통 개발·검증 규칙은 [rules.md](../rules.md)를 따른다. 아래는 목표 동작이며 구현 완료 목록이 아니다. 변경 전 `src/types/game.ts`, `src/config/gameData.ts`와 해당 시스템을 확인한다. 기존 문서 경로는 유지하며, 자동 스킬 탐색에 등록되었다고 가정하지 않는다.

## 1. Room Grid & Progression System

### 1.1 Grid Graph Data
- 방은 $M \times N$ 2차원 배열 노드 구조로 표현.
- 각 룸 노드는 상, 하, 좌, 우 연결 여부를 보유한다. 이 예시는 핵심 필드만 나타내며 실제 타입(`visited`, `waveCount` 포함)은 `src/types/game.ts`를 재사용한다:
  ```typescript
  interface RoomNode {
    id: string;
    gridX: number;
    gridY: number;
    type: 'COMBAT' | 'ELITE' | 'EVENT' | 'RECOVERY' | 'BOSS';
    doors: {
      top: boolean;
      bottom: boolean;
      left: boolean;
      right: boolean;
    };
    cleared: boolean;
  }
  ```

### 1.2 Room State Machine
1. **Entering:** 플레이어가 문을 통해 진입하면 카메라가 해당 룸으로 이동(또는 룸 페이드 전환).
2. **Locked & Waves:** 사방의 문 타일 충돌체가 활성화되며 웨이브 타이머에 따라 적 스폰.
3. **Cleared:** 모든 웨이브의 스폰 완료, 대기 중 스폰 0개, 활성 적 0기를 모두 만족해야 클리어한다. 보상 처리를 마친 뒤 연결된 문만 열고 다음 방 타입 뱃지를 표시한다.
   보스는 처치 즉시 남은 적·탄환·예약 스폰·장판을 정리한다. S1~4는 스테이지 보상과 정비를 거쳐 다음 맵으로 전환하고 S5부터는 저장 후 승리 종료/무한 계속을 선택한다. `StageProgression`의 별도 상태로 중복 보상과 이중 전환을 막는다.
4. **Transition:** 보상 UI가 닫힌 상태에서 열린 문 트리거에 진입하면 다음 `RoomNode`로 한 번만 전이한다. 반대편 문 안쪽 안전 위치에 배치하고 즉시 되돌아가는 재진입을 막는다.

### 1.3 Progression Invariants
- 격자는 `grid[y][x]`로 접근한다. 경계 밖·빈 노드로 문을 연결하지 않고 양쪽 연결이 대칭인지 확인한다. 시작 방에서 보스 방까지 도달 가능해야 한다.
- `ENTERING`, `LOCKED_WAVES`, `CLEARED`, `TRANSITION` 상태 이름은 기존 `RoomState`를 따른다. 보상 대기는 별도 플래그 또는 명시적 상태로 제어하며 모달 중 전투와 출구 이동을 차단한다.
- 방 재방문 시 전투·회복·보상을 중복 실행하지 않는다. 클리어 상태와 보상 수령 상태를 구분해야 하는 변경에는 별도 수령 정보를 추가한다.
- `COMBAT`/`ELITE`는 웨이브와 클리어 보상, `EVENT`는 봉인된 소환진의 안전 회수/도전/지나가기, `RECOVERY`는 최초 방문 회복으로 처리한다. 소환진은 스테이지당 1개이며 안전 회수는 T1 소환권 1장, 도전은 수호자 1기+기본 적 2기와 한 웨이브 전투 후 소환권 1장+일반 방 클리어 재화를 지급한다. 선택·보상은 재방문해도 반복되지 않는다. 기존 저장의 `SHOP`은 로드할 때 `EVENT`로 변환하고 보상·체력은 재지급하지 않는다. S5 이후 `BOSS` 클리어는 진행 선택을 저장하며 종료 선택에서 승리를 확정한다.
- 무한 원정은 `getStageDefinition`/`generateEndlessStage`가 S6부터 5개 테마·기존 보스 패턴을 순환하는 5×5/15방을 제공한다. S1~5 수치는 유지하며 무한 구간은 HP/피해/보상/추가 웨이브/스폰/동시 적 상한과 S1000 안전 종료를 적용한다. v2 `mode`와 `endlessChoice`로 pending/continue/exit를 복원하고, 계속 전환에 소환권 +1·본체 HP 40% 회복을 한 번 적용한다. 최고 도달 기록은 별도 키로 보존한다. 상세는 [무한 원정 결정](../../design/decisions/014-endless-mvp.md)을 따른다.
- 보스 처치와 일반 클리어 경로에서 통계·보상·승리 화면을 중복 처리하지 않는다. 승리/패배는 런당 한 번만 확정하고 종료 후 피해·방 이동을 차단한다.

## 2. Unit Summoning & Combination

### 2.1 Summoning, Recipes & Formation
- 서로 다른 출전 archetype만 계산하는 편성 시너지는 숲2종 분대 공격+5%, 원거리2종 분대 공속+5%, 전열2종 본체/동료 방어+5%이며 각1회/대기 제외/전투 불능 포함이다. 강화/깃발/재능 효과 그룹에서 재계산하고 공속2.5배·방어50% 상한, 현재 HP/영웅 공격·공속 보존을 따른다. 획득22종/토벌5종 도감은 별도 `smash.discovery-codex.v1`로 보존하고 보너스를 주지 않는다. 현재 보유/기존 토벌을 복구하고 판매/소모된 과거 개체는 추정하지 않는다. 손상·읽기 실패는 원본 보존, 쓰기 실패는 메모리 유지/재시도/안내를 적용한다. 보스5종은 `bossData.ts`의 색/패턴 배치·활성 대기/1~1.1초 예고/회피 안내를 실제 사용하며 위험 슬롯/풀을 재사용한다. 상세는 [보스·시너지·도감 결정](../../design/decisions/017-boss-synergy-codex.md)을 따른다.
- 정비의 각성·서비스 메뉴는 ★3 개체 각성0~10(단계당 기본 무기 공격/최대 HP +5%, 비용 `ceil(80*tier*1.35^현재단계)`, 현재 HP 유지), 생존 본체/출전 동료 완치40◆·사망 출전 동료 HP50% 즉시 부활30◆를 제공한다. 투사체 비례 파생 피해는 기존 계산, 영웅/별도 고정 화상·회복·보호막 수치는 유지한다. 각성 개체 조합/판매는 정확한 ID/단계에 대한 소멸 확인이 필요하고 결과에 승계/환불되지 않는다. 유효 서비스 대상/상태·가격·잔액을 검증한 뒤 단일 차감하고 안전 저장한다. S3부터 어떤 보스 최단 경로에도 속하지 않는 COMBAT 후보 하나에 보급고를 표시한다(후보 없으면 없음). 첫 클리어 후 일반 보상 외 소환권2/마력석25를 하나 선택하고 방의 플래그/선택으로 중복을 막는다. 현 스테이지 정비 어디서든 보류 보상을 받고 다음 스테이지 포기는 확인한다. 기존 격자에 소급 추가하지 않는다. 상세는 [각성·서비스·보급고 결정](../../design/decisions/016-awakening-services-side-supply.md)을 따른다.
- Lv.3/6/9/12/15/18 재능을 정비에서 무료 3지선다로 선택하거나 보류한다. 같은 재능 반복·최대 6회이며 분대 지휘 공격 +3%는 강화/깃발과 가산(영웅 제외), 활력 최대 HP +10은 현재 HP 보존, 집중은 치유 파동 18초 대기를 선택마다 1초 줄여 최소 12초다. 치유 파동은 전투 중 생존 본체/출전 동료 각 HP 10 회복, 부활/모두 만피 대기 소비 없음이다. 활성 전투 delta만 대기를 줄이고, 재능과 남은 시간은 안전 저장에 복원한다. 버튼 안에서 해제할 때 시전하며 이탈/취소/blur/일시정지/전환은 취소하고 조이스틱 포인터와 분리한다. 구형 저장은 재능 없음/치유 준비로 달성 레벨 선택을 제공하며 새 런에서 초기화한다. S5 이후 계속 선택의 선택형 변이(강철 HP×1.15/흉포 피해×1.1/질주 속도×1.05, 모두 보상 배율×1.1)는 다음 한 스테이지만 적용한다. 기본 NONE, 최종 상한·제곱근 킬 정책 유지·무효 옵션 비활성·누적 없음이며 현재/확정 다음 변이를 분리 저장한다. 상세는 [재능·액티브·변이 결정](../../design/decisions/015-talents-active-mutations.md)을 따른다.
- 핵심 성장 수단은 재화로 유닛을 소환하고 여러 개체를 재료로 조합하는 것이다. 능력치 강화는 보조 선택지로 둔다.
- 정예 방 첫 클리어에 유물 선택 보상을 기록하고 기존 마력석도 지급한다. 정비에서 미보유 유물 하나를 무료 선택하거나 보류하며, 하단 유물 버튼으로 다시 연다. 고유 유물 3개, 확정+보류 최대 3개, 획득 순서대로 선택한다. 깃발은 분대 공격 +10%를 강화와 합산, 성배는 전투 5초마다 생존 본체/출전 동료 HP 2 회복, 인장은 수동 조합/승급·간편 제작의 추가 조합비 10% 할인(비용별 올림, 소환 비용 제외)이다. 현재/과거 방 출처·정예 수·고유 ID·보류/확정·성배 남은 시간을 저장/검증한다. 재접속에서 재획득/즉시 회복하지 않고 새 런에서 초기화한다. 상세는 [유물 MVP 결정](../../design/decisions/013-relic-mvp.md)을 따른다.
- 정비 화면 ‘원정 강화’에서 분대 공격/공속/체력·영웅 공격/체력·공통 방어 6종을 구매한다. 효과·가격·상한은 `src/config/upgradeData.ts`, 원천/레벨 거래는 `SquadRoster`, 효과 재계산은 `UpgradeEffects`가 기준이다. 각 Lv.10, 현재 단계별 비용 `ceil(base * 1.35 ** L)`. 오래된 견적·부족 자금·상한 구매는 무변경이다. 성공한 거래를 지출 기록하고 즉시 저장한다. HP 강화는 기존 현재 HP/사망·부활/스킬 대기·보호막을 유지하며 새 소환은 강화 최대 HP로 시작한다. 공속은 기존 배율과 합쳐 최대 2.5배, 방어는 본체/동료 피해를 최대 50% 줄인 뒤 보호막에 적용한다. 원정 중 유지·새 런 초기화, 강화 정보 없는 v1/v2는 모두 0단계다. 상세 수치/원천별 계산/저장/예외는 [강화소 결정](../../design/decisions/012-expedition-upgrades.md)을 따른다.
- 본체 기본 클래스는 견습 소환사다. 전투 중 가까운 적(사거리 260)에게 이동하면서 1.1초마다 자동 사격하며 Lv.1 공격력 8, 최대 HP 100에서 레벨당 +1/+5, Lv.20 상한이다. 모든 원천의 처치로 XP를 얻고 여러 레벨 상승을 처리하되 현재 HP는 회복하지 않는다. 분대/★/드루이드 버프는 영웅에 적용하지 않는다. 영웅·분대·환경 처치는 적 생명별 한 번만 기록하고 영웅 처치가 분대 처치 스킬을 발동하지 않는다. HUD/종료 통계에 성장과 원천별 처치를 표시한다. 영웅 정보 없는 v1/v2는 기존 HP/재화 보존+Lv.1/XP 0, 신규 v2는 성장·처치·남은 사격 시간을 저장한다. 사격 대기는 정비/백그라운드 중 정지한다. 수치/효과 계산/예외/검증은 [영웅 MVP 결정](../../design/decisions/011-apprentice-hero.md)을 따른다.
- 타이틀 ‘영혼의 야영지’에서 견습/기사/원소 술사 선택과 영구 HP/공격 각5단계를 구매한다. `heroClassData.ts`가 클래스 전투·회복/정화 수치, `LegacyProfile`이 별도 영구 키의 최초 토벌 영수증·조각·구매 원천이다. 클래스별 첫 스토리 보스마다3조각(전체45), 다음 단계 비용1~5, 숙련은 기록만 제공한다. 지급/영수증·구매/차감을 단일 키 쓰기로 확정하고 실패 보류는 사용 불가·재시도 안내한다. 손상 원본은 보존한다. 모든 쓰기 실패 뒤 런도 남지 않은 앱 종료에서는 미저장 보류 유실 가능성을 안내한다. 선택/성장은 다음 새 런에만 적용하며 이어하기는 HeroSnapshot의 클래스/영구 단계 사본과 HP/대기를 유지한다. 단계 없는 옛 저장은0이다. 상세는 [12단계 결정](../../design/decisions/018-legacy-growth-classes.md)을 따른다.
- 소환 유닛은 각자 위치·이동·대상·사거리·공격 주기를 갖는 독립 전투 개체로 설계한다. 기본안은 비전투 시 본체를 따라 집결하고 전투 시 근접/원거리/지원 역할에 따라 행동하는 방식이다.
- 본체는 이동과 생존을 담당하며 체력이 소진되면 패배한다. 적은 300px 내 전열을 우선하고 그 외에는 가까운 본체/유닛을 공격한다. 개별 유닛은 체력 소진 시 전투 불능이 되며 12초 후 또는 실제 방 이동 시 HP 50%로 부활한다. 생존 동료도 방 이동 때 HP 최소 50%를 받으므로 이동 직전 사망이 HP 면에서 유리하지 않다. 본체에는 이동 회복이 없다. 치유의 샘 최초 방문은 본체와 생존 출전 동료에 각 최대 HP 45%를 추가 회복하고 중복 지급하지 않는다. 이어하기는 HP를 그대로 복원한다. 정비/백그라운드 일시정지의 남은 자동 부활 시간을 보존한다. 상세는 [회복·부활 결정](../../design/decisions/010-recovery-and-revival.md)을 따른다. 지원은 3초마다 본체와 생존 동료를 회복하며, 성기사/수호신은 본체 피해의 30%/40%를 대신 받는다.
- 지원의 ★1 대상별 회복량은 약초 사제 3, 달빛 사제 4, 드루이드 6이며 기존 ★ 배율을 적용한다. 약초 사제만 로드맵 3단계에서 2→3으로 조정했다. 실제 코드의 피해/회복을 통제 조건에서 비교하는 도구와 기본 OFF인 선택형 전투 계측은 [3단계 기록](../../design/decisions/009-recipe-support-review.md)을 따른다. 인간 플레이 전체의 생존·밸런스 실측과 구분한다.
- 전투 HUD 초상화는 전투 불능 시 자동 부활 남은 초, 불사조 군주/대지의 수호신은 주요 스킬 재사용 대기와 준비 게이지를 표시한다. 초상화를 누르면 실제 HP·부활/스킬 상태·보호막 잔량과 남은 시간을 확인한다. 상세 정보가 열려 있어도 전투는 계속되며 방 이동/편성 제거 시 상세를 닫는다. 표시 기준과 예외는 [전투 상태 HUD 결정](../../design/decisions/006-combat-status-hud.md)을 따른다.
- 방 클리어 후 `SquadScene`에서 지정 소환·조합한다. 클리어한 방에서는 하단 정비 버튼으로 다시 열 수 있다. 일반/정예 방은 최초 클리어 시 재화를 지급하고 회복/소환진은 각 방의 일회성 처리 규칙을 따른다. 맵 전용 상점은 제거했다.
- 보유 한도 16기, 출전 한도 6기를 구분한다. 출전 자리가 없으면 소환 결과는 대기 상태로 보관한다. 전투 불능 상태를 막기 위해 최소 1기는 출전해야 한다.
- 정비 화면 상단 `간편 제작`에서 티어와 유닛을 고르면 새 재료의 소환·중간 조합 비용을 합산해 ★1 결과를 일괄 제작한다. 보유 유닛·★·소환권은 보존하며 재화만 사용한다. 완성 유닛 한 자리만 필요하고 출전이 가득 차면 대기로 받는다. 비용 확인 후 현재 견적·자금·공간을 다시 검사하고 실패 시 거래 전체를 유지한다. 기존 수동 조합/승급은 유지한다. 상세: [간편 제작 결정](../../design/decisions/005-quick-craft.md).
- 레시피는 `src/types/game.ts`의 `CombinationRecipe`/`IngredientSpec`을 사용한다. 기존 고정 재료와 속성·역할·티어 쿼리를 지원하며, 고정 > 조건 > 승급 순으로 표시하고 플레이어가 선택한다. 동일 유닛·동일 ★ 3기는 ★2/★3으로 승급한다. 기본 재료 선택은 미배치 > 낮은 ★ > 낮은 티어이며 UI에서 실제 인스턴스를 직접 변경할 수 있다.
- 실제 소환 비용·조합표·보상·역할별 이동은 `src/config/squadData.ts`가 기준이다. 예: 숲의 사수 2기 → 바람 순찰자, 숲의 사수 + 바람 순찰자 → 서리 현자, 불꽃 마법사 + 서리 현자 + 마력석 10개 → 황혼 대마법사. 이 조합표는 프로젝트용이며 원작 규칙이 아니다.
- UI는 결과, 필요 재료, 보유 수, 실제 소모 개체와 비용을 표시하고 플레이어가 확정한다. 부족한 재료를 보고 다음 소환·구매 목표를 정할 수 있어야 한다.
- 소환 확정 시 잔액·공간을 검사하고 비용 차감과 개체 추가를 한 번에 처리한다. 조합 확정 시 재료 종류·수량·인스턴스 중복·잔액·변경 후 보유/배치 공간을 다시 검사한다. 실패하면 재료와 재화를 유지한다.
- 배치 중인 재료를 소모하면 전투 개체와 예약 공격을 정리한다. 결과 생성과 배치 갱신은 한 번만 처리하고 방 이동 시 소모된 유닛이 복원되지 않게 한다.
- 방 보상은 소환 재화·유닛·조합 재료 획득을 지원한다. 소환·조합 후에도 보유 목록과 배치 상태가 일치해야 한다.

### 2.2 Runtime State & Movement
- `SquadRoster`를 보유·재화·조합 거래의 기준으로 사용한다. 전투 개체는 출전 목록에서 생성하며 정비 종료 시 `PlayerSquad.syncRoster()`로 소모/대기 유닛을 제거하고 신규 유닛을 반영한다.
- 각 유닛은 전투 중 적에게 접근해 역할별 목표 사거리를 유지하고, 적이 없으면 본체 뒤 대형으로 집결한다. 본체 주위를 공전하지 않는다. 사거리 안에 활성 적이 없으면 발사하지 않는다.
- 기존 `DroneArchetype`/`DroneSpec` 타입과 스프라이트는 무기·외형 재사용을 위해 유지한다. 타입 이름을 이유로 단일 유닛 강화 방식으로 되돌리지 않는다.
- 소환·조합은 정지된 정비 화면에서 수행하며 매 거래 후 상태를 다시 표시한다. 방 이동 시 보유/배치를 유지하고 새 런은 기본 사수 2기와 30 M으로 시작한다.
- 중간 스테이지 보상은 일반/정예 방 예상 수입의 60%와 T1 무료 지정 소환권 1장이다. 보유가 가득 차면 소환권을 보존한다. 다음 스테이지 진입 시 본체 최대 체력의 40%를 회복한다. 기존 직접 소환은 유지하되 T3 이상 직접 소환은 STAGE 3부터 개방한다.
- 적 처치 재화는 `round(mineralValue * sqrt(rewardMult))`를 적용한다. 보스 적의 처치 재화도 포함하지만 별도의 방/스테이지 클리어 보상은 기존 배율을 유지한다. 기존 저장 잔액은 소급 변경하지 않는다. [킬 보상 결정](../../design/decisions/008-kill-reward-curve.md)을 따른다.
- `RunSaveManager`는 스테이지 첫 방 진입, 방 보상 확정, 성공한 정비 거래와 정비 종료에 v2 자동 저장한다. 타이틀 이어하기는 같은 격자·현재 방·본체/출전 유닛 HP·부활/회복/주요 스킬 남은 시간·보유/배치·★·재화·소환권·강화·통계를 복원하며 보상/전환 회복을 재실행하지 않는다. 정비 도중 중단해도 성공한 거래를 유지한다. 전투 도중 중단하면 마지막 정상 저장 지점으로 돌아간다. v1 스테이지 시작 저장 및 옛 `SHOP` 라벨도 읽고 다음 정상 저장부터 v2로 쓴다. 최신본 손상 시 이전 정상본을 안내와 함께 사용한다. 승리·패배 시 두 저장본을 종료하고 새 게임의 교체는 UI에서 확인한다. 초기 정책은 [v1 결정](../../design/decisions/001-stage-checkpoints.md), 현재 정책은 [로드맵 0~1단계 결정](../../design/decisions/007-roadmap-foundations.md)을 따른다.
- 이동량은 초 단위 delta, `fireRateMs`와 효과 지속시간은 밀리초 기준을 사용한다.

## 3. Combat Loop & Arcade Physics Implementation

### 3.1 Object Pooling Pipeline
- `Phaser.Physics.Arcade.Group`을 상속한 `BulletPool`과 `EnemyPool` 클래스 구현:
  ```typescript
  export class BulletGroup extends Phaser.Physics.Arcade.Group {
    constructor(scene: Phaser.Scene) {
      super(scene.physics.world, scene, {
        classType: Bullet,
        maxSize: 150,
        runChildUpdate: true
      });
    }
    // 발사 구현은 src/entities/Bullet.ts의 BulletFireConfig 계약을 따른다.
  }
  ```

위 코드는 그룹 구성의 축약 예시다. 기존 `BulletGroup`/적 풀을 우선 확장하고 같은 역할의 풀을 중복 생성하지 않는다.

### 3.2 Pool & Damage Invariants
- 풀 고갈 시 탄환/시각 효과는 생략할 수 있다. 필수 적 스폰은 재시도하거나 명시적 대기열로 관리하며 실제 생성되지 않은 적을 활성 적 수에 포함하지 않는다.
- 재활성화 시 체력·속도·바디·색상·크기·수명·디버프·관통/연쇄 잔여 횟수·피격 기록을 초기화한다. 반환 시 렌더링과 물리를 모두 비활성화하고 관련 타이머/트윈을 정리한다.
- 한 적의 사망은 한 번만 처리한다. 같은 프레임의 직접 피해·폭발·연쇄 피해가 겹쳐도 처치 수와 재화를 중복 지급하지 않는다.
- 관통탄은 발사 한 번당 같은 적에게 중복 적중하지 않고 연쇄 번개는 같은 연쇄 안에서 이미 맞은 적을 다시 선택하지 않는다. 풀 객체 재사용 시 이전 개체의 피격 기록이 새 개체에 적용되지 않게 생명 주기 ID 등을 사용한다.
- 폭발의 직접 타격 대상 포함 여부, 연쇄 최대 횟수, 감속 중첩 규칙을 정의한다. 기본 감속은 가장 강한 효과를 우선하고 만료 시 기본 속도로 복원한다.
- 접촉 피해에는 무적 시간을 적용해 프레임 수에 따라 피해량이 달라지지 않게 한다. 방 이동 시 남은 탄환과 적, 예약 스폰을 정리한다.

### 3.3 Enemy Swarm AI
- 기본 추적은 본체/유닛 타깃 방향으로 이동한다. 스테이지별 포자 사수의 원거리 범위 공격·폭발형·소환형을 도입하며 방어형·돌격형은 기존 적을 재사용한다. 보스는 돌진·독 장판·낙하·감속장·소환 패턴과 1~3페이즈를 사용한다. 일반 적은 0.8초, 보스는 프로필별1~1.1초 예고 후 실행하며 장판은 공용 고정 크기 슬롯을 재사용한다.
- 무리 겹침 방지: 적 유닛 간 가벼운 충돌(`collider`) 또는 밀어내기 반발력 적용.

## 4. Mobile Packaging (Capacitor Setup)

현재 저장소에는 `capacitor.config.json`과 `android/`가 있다. 일반 수정에서는 초기화/플랫폼 추가를 반복하지 않는다.

- 웹 개발: `npm run dev`
- 웹 빌드 및 타입 검사: `npm run build`
- Android 동기화: `npm run cap:sync` (빌드 후 `npx cap sync android` 실행)
- 네이티브 실행/패키징은 Android SDK·JDK 환경이 있는 경우 수행하며 웹 빌드 성공과 APK/기기 검증 성공을 구분한다.

1. **Vite Build:** `vite.config.ts`의 `base`를 `'./'`로 설정하여 상대 경로 리소스 로딩 보장.
2. **Capacitor Init (새 프로젝트를 구성할 때만):**
   ```bash
   npx cap init SmashRoguelike com.yourstudio.smashroguelike --web-dir dist
   npm run build
   npx cap add android
   npx cap sync
   ```
3. **Android Safe Area & Immersive Mode:**
   - 전체화면 설정과 별개로 시스템 바·디스플레이 컷아웃·제스처 영역이 HUD/조이스틱을 가리지 않게 안전 여백을 적용한다.
   - 적용 중인 Capacitor/Android 버전과 테마를 확인하고 실제 기기에서 뒤로가기, 앱 복귀, 화면 크기 변경을 확인한다.
