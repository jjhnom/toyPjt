# 031 — 전투 HUD 컴포넌트와 목업 배치 적용

> 후속: 2026-11-12 사용자가 실제 목업 경로를 제공했다. [032 — 실제 상단 목업 반영](032-reference-top-hud.md)에서 직접 대비·수정을 진행했다. 아래는 목업 경로 확인 전의 작업 기록이다.

## 목적과 기준

- 요청: 720×1280 Phaser 화면에 상단/배너/6슬롯/하단 조작을 적용하고 기존 전투·소환·저장·자유 터치 이동을 유지한다.
- 로컬 origin은 `https://github.com/jjhnom/toyPjt.git`이다. 로컬에서 수정·검증하고 push/merge하지 않는다.
- 이번 메시지에 새 목업 첨부는 보이지 않았다. 저장소의 `.agent/skills/design/mockups/04_battle.png`는 이전 콘셉트로, 이번에 요청한 6슬롯·조작 배치를 그대로 담고 있지 않다. 따라서 명시된 배치/색상을 우선하고 기존 에셋을 사용한다. 새 목업과의 픽셀 일치를 주장하지 않는다.

| 영역 | 현재 좌표/크기 | depth·입력 | 갱신 |
|---|---|---|---|

| 분대 | y=1080~1180, 슬롯6개 x=8+94i | 패널50~51, 초상화53, 상태56, 상세65 | `refreshHud` 및 `updateHudVitals` |

- `ARENA_BOUNDS`: x=64~656, y=170~1090. 배너 하단260은 상단 전투 시야와 겹친다.
- `BootScene`은 제공 UI atlas와 기존 캐릭터/아이콘을 로드한다. 장식 PNG에 실시간 텍스트를 합성하지 않는다.
- 현재 6슬롯에는 빈 슬롯 + 및 개별 슬롯 선택 입력이 없고, 체력은 막대로만 표시된다.

## 구현 순서와 완료 조건

1. `BattleTopHud`: 좌측 초상화/이름/레벨, 중앙 HP/EXP, 우측 재화, 최우측 미니맵. 기존 scene 필드에는 컴포넌트 객체를 연결해 갱신 경로를 보존한다.
2. `StageBanner`: 전체 상단을 y=164 안에 배치한다. 긴 지역 이름은 글자 크기 축소/말줄임 없이 페이지로 순환 표시한다. 전투 상태 문구는 기존 이벤트에서 갱신한다.
3. `BattleSquadHud`: 6슬롯/등급/HP/선택/빈 슬롯 +, 그룹화된 요약, 우측 상세. 기존 상세 창과 선택 ID를 사용한다.
4. `BattleControlHud`: 기존 정비·액티브·타이틀 콜백을 연결하고 간격과 주요 행동의 강조를 조정한다. 존재하지 않는 자유 파밍 기능은 추가하지 않는다.
5. 조이스틱 자유 터치·멀티터치·취소·포커스·UI 차단 검증.
6. HUD 전용 색상 토큰을 지정값으로 맞추고 기존 NineSlice/이미지를 재사용한다.
7. 각 구현 단계와 최종 360·390px 실제 Phaser 화면을 캡처하고 테스트·빌드·회귀를 실행한다.

## 구현 결과

- `BattleTopHud.ts`: (12,8) 540×82. 초상화/이름/레벨은 좌측, HP/EXP는 중앙, 재화는 우측이다. 미니맵은 (564,8) 144×82이며 기존 미니맵 그래픽의 좌표·의미를 유지한 채 0.5배로 표시한다.
- `StageBanner.ts`: (12,92) 696×64, 하단 y=156. 기존 상단 문 스프라이트의 상단 y=159보다 위에 있으며 물리 경계·문 위치를 바꾸지 않았다. 긴 이름과 안내는 2.4초마다 원문 페이지를 순환한다. 상태 갱신은 이름의 순환을 초기화하지 않고 씬 종료 시 타이머를 정리한다.
- `BattleSquadHud.ts`: 6개 슬롯에 초상화/별/체력 수치·막대/상태/선택 테두리를 표시한다. 빈 슬롯은 어두운 프레임과 +로 표시하며, 슬롯 터치는 기존 선택 ID와 상세 창을 연다. 요약은 출전/보유/시너지/생존으로 정렬했다.
- `BattleControlHud.ts`: 정비(중심370), 기존 액티브(516), 타이틀(652), y=1230. hit 간격은 각각20·24이며 모든 버튼 hit가 최소112×100(정비140×100)이다. 정비는 가능할 때 금색 주요 버튼으로 표시하고 불가능할 때 실제 전투/이동 상태를 표시한다.
- `GameScene.ts`의 전투/성장/거래/저장 데이터는 기존 소유자와 갱신 경로를 유지한다. 기존 브라우저 검증용 HUD 참조는 컴포넌트 객체의 별칭으로 연결했다.
- `fantasyTheme.ts`의 HUD 전용 색상은 요청한 배경/패널/보라/금색/HP/EXP/생존 색을 사용한다. 제공 NineSlice와 아이콘을 재사용하고 새로운 PNG·의존성을 추가하지 않았다.
- `ActiveSkillButton.ts`에는 위치 지정 API와 진행 막대 색상만 추가/수정했다. 이번 작업에서 `VirtualJoystick.ts`, `BootScene.ts`, `gameData.ts`의 이동/로딩/경계 코드는 수정하지 않았다.

## 검증 기록

- `npm test`: 148/148 통과.
- `npm run build`: TypeScript strict와 Vite 빌드 통과. 기존 번들 크기 경고가 남는다.
- `node tests/hud-mockup-browser.mjs baseline|top|stage|squad|controls|final`: 각 구현 단계의 실제 360·390px 캡처. 최종 검사에서 6슬롯, 겹침, 상단 문과 배너 분리, 큰 재화, HP/XP/레벨 변경, 긴 이름의 원문 순환, 슬롯 선택/상세, 빈 슬롯 +, 실제 자유 터치 이동, 이동 중 상세 버튼의 두 번째 터치, touchcancel·blur 후 입력 해제를 검증했다.
- 실제 이동 확인: 중앙 x=360에서 드래그 후 x>400으로 이동했고 방향 입력은0.9375였다. 취소 후 포인터·방향·본체 이동 속도가0으로 돌아갔다. 이는 통제된 실제 Phaser 실행 결과다.
- 전투 바닥576×904, 본체 물리 폭36, 상단 문 중심 y=170과 기존 트리거를 유지했다. HUD 배너 하단156 < 문 스프라이트 상단159를 검증했다.
- `node tests/browser-smoke.mjs`: 기존 전투·소환/조합·편성·정비·보스·5스테이지 진행·저장/이어하기·재시작·모바일 입력 회귀 통과.
- `node tests/hero-browser.mjs`: 실제 처치·HP/XP/레벨 연동, 저장 복원, 일시정지, 재시작 통과.
- `node tests/hud-readability-browser.mjs after`: 큰 수치·최대 레벨·긴 보조 문구·저장 실패·보스·S1000의 8개 경계 사례 통과.
- `node tests/battle-redesign-browser.mjs final`: 320·360·720px 전투·보스·효과 및 상세 검증 통과. 기존 비교 페이지도 최종 이미지로 갱신했다.
- 기존 가독성/영웅/전투 브라우저 검증의 좌표·개별 텍스트 계약도 새 배치에 맞췄다.
- 최종 리뷰: 컴포넌트와 GameScene 바인딩, HUD 갱신 캐시, 선택/상세 입력, 액티브 리스너 해제, 페이지 타이머 수명주기를 검토했다. 이번 변경에서 추가 회귀 문제를 발견하지 않았다. 모바일 실기기 검증은 리뷰 범위에 포함하지 않는다.
- 검증 환경은 Windows Headless Chrome157, 720×1280 논리 화면 및 360·390px 모바일 에뮬레이션이다. 소프트웨어 렌더링 환경의 결과를 실제 기기 FPS로 해석하지 않는다.
- 실행 중 C 드라이브가 가득 차 Chrome이 실행되지 않았다. 검증 도구가 만든 임시 프로필만 정리하고 후속 Chrome 프로필은 D 드라이브 작업 영역으로 지정해 복구했다. 영웅 검사 첫 실행의 에셋 로딩 지연은 에셋 HTTP200 확인 후 재실행으로 통과했다.
