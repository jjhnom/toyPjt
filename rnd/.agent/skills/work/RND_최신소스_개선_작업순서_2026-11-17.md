## 0. 현재 상태와 판단 근거

- **확인된 CI 실패:** [GitHub Actions #43974390351](https://github.com/jjhnom/toyPjt/actions/runs/43974390351). 최신 기준 커밋에서 `npm test` 262개 중 **261개 통과, 1개 실패**. 이후 웹 빌드·Android APK 빌드는 실행되지 않음.
- **실패 원인(확인):** `rnd/tests/bgm.test.mjs`의 원본 음원 비교 테스트가 `.agent/skills/sound/20261116/audio/ogg/bgm_lobby_summoners_refuge.ogg`를 읽으려 했으나 해당 경로가 GitHub 체크아웃에 없음(`ENOENT`). `rnd/public/audio/bgm/`에는 배포 대상 음원 3곡이 존재함.
- **최근 개선(코드 확인):** 보스 6종(사막의 제왕 포함), 19개 보스 패턴 조합, 전용 보스 비주얼·모션·VFX 및 보스 효과음 26개, 로비/일반 전투/황혼의 마왕 BGM 3곡 연결.
- **아직 검증되지 않은 부분:** 최신 커밋의 브라우저 통합 테스트, 최신 Android APK 완성 여부, 실제 기기 프레임타임/메모리, 사람 플레이 밸런스.
- **주의:** CI 오류 외 나머지 항목은 코드상 위험 또는 개선 제안이며, 실제 재현 없이 확정 버그로 기록하지 않는다.

## 2단계 (P1) — 모바일 입력·앱 수명주기 안정화

**목표:** 실제 Android 환경에서 이동, 스킬, 모달 및 앱 복귀가 충돌하지 않도록 한다.

**관련 파일**
- `rnd/src/ui/VirtualJoystick.ts` — 현재 `pointer.y < 160`만 검사하여 상단 외 대부분의 터치를 선점할 여지가 있음.
- `rnd/src/scenes/GameScene.ts`
- `rnd/src/systems/soundLifecycle.ts`
- 관련 모바일 입력 브라우저 테스트(`rnd/tests/*browser.mjs`)

**작업 체크리스트**
- [ ] 조이스틱 시작 가능 영역을 **화면 왼쪽 아래**로 제한(실제 좌표·UI 배치에 근거해 결정).
- [ ] 버튼, 미니맵, HUD, 팝업 입력과 조이스틱이 서로 터치를 빼앗지 않도록 인터랙션 우선순위 정의.
- [ ] 이동을 먼저 누른 경우와 스킬을 먼저 누른 경우 **모두** 멀티터치 동작 검증.
- [ ] `pointerupoutside`, 터치 취소, 포커스 상실, 모달 진입 시 조이스틱 방향·속도 초기화.
- [ ] 백그라운드 전환/복귀 시 스폰·피해·타이머·사운드가 잘못 재개되지 않는지 확인.
- [ ] 세로 화면, 화면비 변화, 노치/시스템 제스처, 저해상도 폰에서 입력 가능 영역 확인.

**필수 시나리오**
1. 왼손 이동 → 오른손 스킬 → 오른손 해제 → 계속 이동.
2. 오른손 스킬 → 왼손 이동 → 스킬 해제 → 계속 이동.
3. 이동 중 홈/잠금 → 앱 복귀 → 이동 멈춤, 허위 입력 없음.
4. 이동 중 보상/정비 모달 열기 → 전투가 비활성인 동안 움직임·공격 없음.
5. 앱 복귀 직후 저장된 체력/재화/쿨타임 정상 유지.

**완료 기준:** 자동 입력 회귀 테스트 통과 + 실제 Android 기기에서 위 시나리오 수동 검증 기록. 브라우저 에뮬레이션 통과를 실기기 통과로 표시하지 않는다.

**예상 산출물:** 입력 안정화 PR, 재현 영상/스크린샷, 기기 정보와 테스트 결과.

## 3단계 (P2) — 보스 스킬 연출·타격감 개선

**목표:** 보스마다 스킬이 한눈에 구분되고, 예고 → 발동 → 충격 → 잔상의 타이밍과 실제 피해 판정이 일치하도록 한다.

**관련 파일**
- `rnd/src/config/bossData.ts`
- `rnd/src/entities/EncounterHazards.ts`
- `rnd/src/ui/BossVfxController.ts`
- `rnd/src/ui/BossMotion.ts`
- `rnd/src/systems/BossAudioController.ts`
- `rnd/src/config/bossSoundData.ts`
- `rnd/src/ui/lavaMeteorVfx.ts`, `frostQueenVfx.ts`, `forestSlamVfx.ts`, `bossSandstorm.ts` 등 전용 VFX 파일

**작업 체크리스트**
- [ ] 보스별 주요 공격을 프레임 단위(예고 시작, 피격 판정, 충격 이펙트 시작, 종료)로 대조.
- [ ] 예고 범위와 실제 충돌 범위 일치: 원형·선형·추적형·연속 폭격 각각 검사.
- [ ] **연속 충격음**(예: 서리 여왕 다연속 빙하 폭격)을 중복 억제 정책과 양립시키도록 설계: 시전 1회, 약한 연속 임팩트, 마지막 강한 임팩트.
- [ ] 보스별 고유한 색상뿐 아니라 **실루엣·모션·파편·잔상·바닥 패턴** 차별화.
- [ ] 충격 시 화면 흔들림/화이트 플래시/히트스톱 등은 짧고 제한적으로 적용하며, 접근성 설정(화면 흔들림 줄이기) 고려.
- [ ] VFX 예외 발생 후 `visualFailed`가 계속 참으로 남아 추가 효과가 비활성화되는 위험 검토. 최소한 로그/복구/재초기화 조건 마련.
- [ ] 화려한 이펙트가 경고 영역과 플레이어/아군을 가리는지 모바일 화면에서 확인.

**보스별 점검표**

| 보스 | 대표 기술 | 중점 확인 |
| --- | --- | --- |
| 숲의 수호자 | 돌진, 대지 강타, 뿌리 포위 | 강타 실제 판정과 균열·뿌리 예고 일치 |
| 독 늪의 군주 | 독 장판, 돌진, 포자탄 | 독 웅덩이와 암흑 구속의 비주얼 차별화, 포자탄 경로 |
| 용암 거신 | 운석 낙하, 균열 | 낙하 예고 → 강하 → 폭발 → 지면 균열 연계 |
| 서리 여왕 | 빙결 고리, 소환, 연속 폭격 | 다연속 충격 타이밍, 얼음 범위, SFX 강약 |
| 황혼의 마왕 | 암흑 구속, 운석, 참격 등 | 사슬/룬/그림자, 2회 참격 방향 경고 |
| 사막의 제왕 | 추적 모래폭풍, 사막의 송곳니 | 추적 범위·이동 속도·안전지대 가독성 |

**완료 기준**
- [ ] 각 보스 대표 기술의 **예고/충돌/효과**가 프레임·좌표 기준으로 일치.
- [ ] 보스별 기술 비교 스크린샷 또는 짧은 영상 제공.
- [ ] 기존 피해량·쿨타임·보상은 명시적 승인 없이 변경하지 않음.
- [ ] VFX 활성 수, FPS, 오류 카운터를 함께 확인.

**예상 산출물:** 보스별 독립 PR(예: 용암 → 황혼 → 서리 순), 테스트 캡처 및 비교 자료.

## 6단계 (P2) — GameScene 책임 분리 및 확장성 강화

**목표:** 게임 기능을 보존하면서 복잡도를 낮추고 다음 보스·유닛 추가 시 수정 범위를 줄인다.

**현재 관찰:** 최신 `rnd/src/scenes/GameScene.ts` 약 1,798줄. 보스 VFX·오디오는 분리됐으나 전투 관리/방 이동/웨이브/HUD 등 조율 책임이 집중.

**권장 책임 분리 후보**
- `WaveController` — 적 등장 요청과 웨이브 상태.
- `BossCombatController` — 보스 패턴 계획과 페이즈 진행 조율.
- `RoomTransitionController` — 방 클리어·입장·정리·복귀.
- `BattleHudController` — 전투 HUD 업데이트와 출력 캐시.
- 기존 `BossVfxController`, `BossAudioController`, `EncounterHazards`는 역할 유지.

**작업 체크리스트**
- [ ] 코드 이동 전에 현재 이벤트/상태 소유권 다이어그램 작성.
- [ ] 한 번에 한 책임만 분리하고 **게임 동작 변경 없이** 회귀 테스트 통과.

## AI 에이전트 공통 실행 원칙

1. `rnd/AGENTS.md`, `rnd/.agent/rules.md`, 관련 Skills를 먼저 읽는다.
2. 해당 PR 범위의 현재 구현·호출자·테스트를 읽고 **수정할 파일을 먼저 제안**한다.

4. 기존 소환·조합·전투·저장·경제 규칙은 사용자 승인 없이 변경하지 않는다.

6. 새 의존성, 대규모 리팩터링, Android 서명/배포, Git push/merge는 사용자 사전 승인 후 진행한다.
7. 변경 후 실행한 명령과 실제 결과(성공·실패·미실행)를 한국어로 보고한다.
8. 기존 버그/추정 위험/선택적 개선 사항을 명확하게 구분한다.
