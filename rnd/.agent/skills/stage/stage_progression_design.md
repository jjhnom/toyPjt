# Stage Progression & Difficulty Scaling Design (목표 설계 문서)

> **상태: 목표 설계안. 아래 구현 범위 외 항목은 완료 목록이 아니다.** 구현 전에 `src/types/game.ts`, `src/config/gameData.ts`, `src/systems/RoomGridManager.ts`를 읽고 기존 타입을 재사용한다.
> 모든 수치는 **초기 제안값**이며 실측 플레이로 조정한다. 최종 값은 `src/config/stageData.ts`에서 관리한다. 공통 규칙은 [rules.md](../../rules.md)를 따르고 같은 규칙을 복제하지 않는다.

### 2026-11-04 구현 범위

- 5개 스테이지, 가변 직사각형 연결 격자와 각 7/9/11/13/15개 방, 스테이지당 상점·회복·보스 각 1개를 구현했다.
- `StageProgression`의 보스 보상/전환 중복 방지, 중간 보스 → 정비 → 새 맵, 최종 보스만 승리하는 흐름과 HUD·통계를 구현했다.
- 스테이지/거리/웨이브별 체력, 공격력·속도·웨이브·스폰 간격·활성 적 제한·재화 배율, 필수 적 스폰 대기열을 적용했다.
- 중간 보상은 예상 방 수입의 60% + T1 무료 지정 소환권 1장, 다음 스테이지 진입 회복은 최대 HP 40%다. 가득 찬 보유 목록에서도 소환권은 소실되지 않는다.
- 적 종류 3개와 보스 돌진·장판·낙하·감속·소환, 1~3페이즈 및 0.8초 공격 예고를 연결했다. 단계 전환은 즉시 격자를 교체하고 배너를 표시하며 별도 페이드는 사용하지 않는다.
- 런 저장/복원, 긴 플레이를 통한 35~50분 경제·난이도 조정, 실제 Android 기기 성능 검증은 미완료다. 아래 시간/편성 목표는 아직 실측 결과가 아니다.

## 1. 문제와 목표

**현재:** 격자 한 장 → 보스 처치 → 승리로 런이 끝난다 (스킬 §1.3 "BOSS는 최종 전투와 승리").

**목표:** 하나의 맵(스테이지)에서 보스를 잡으면 다음 맵으로 넘어가고, 스테이지가 올라갈수록 일반 적과 보스가 강해진다. 최종 스테이지 보스를 잡아야 승리한다.

**새 루프:**

```
[런 시작] → Stage 1 맵 → 방 진행 → 보스 처치
        → 스테이지 클리어 보상/정비 → Stage 2 맵(새 격자) → … → 최종 보스 처치 → 승리
```

**용어:** 런(Run) ⊃ 스테이지(Stage, 한 장의 격자 맵) ⊃ 룸(Room).

## 2. 구조 변경

### 2.1 데이터 계약 (제안)

`src/types/game.ts`에 먼저 추가한다. 기존 `RoomNode`, `RoomState`는 그대로 재사용한다.

```typescript
interface StageDef {
  index: number;               // 0부터. 표시는 index + 1
  themeId: string;             // 배경 팔레트·타일 테마
  gridWidth: number;           // M
  gridHeight: number;          // N
  roomCount: number;           // 전투/정예/상점/회복 포함 총 방 수
  enemyPoolIds: string[];      // 이 스테이지에서 등장 가능한 적 종류
  newEnemyIds: string[];       // 이 스테이지에서 처음 등장 (도감/예고용)
  bossId: string;
  isFinal: boolean;
}

interface StageScaling {       // 스테이지 인덱스로부터 계산되는 배율
  enemyHpMult: number;
  enemyDamageMult: number;
  enemySpeedMult: number;      // 상한 있음
  waveCountBonus: number;
  spawnIntervalMult: number;   // 1보다 작을수록 빠름, 하한 있음
  rewardMult: number;
  bossHpMult: number;
  bossDamageMult: number;
}
```

런 상태에 `stageIndex`를 추가한다. 룸 이동에는 유지되고 새 게임에서는 0으로 초기화된다 (rules §6).

### 2.2 상태 흐름

| 단계 | 동작 |
| --- | --- |
| 보스 룸 클리어 | 보스 처치 1회 확정 → 마지막 스테이지면 **승리**, 아니면 **스테이지 클리어** |
| 스테이지 클리어 | 스테이지 보상 지급(1회) → `SquadScene` 정비 → "다음 스테이지로" 확정 |
| 스테이지 전환 | 현재 전투 개체·탄환·적·예약 스폰·타이머 정리 → 새 `StageDef`로 격자 생성 → 시작 방 진입 |

- 기존 `RoomState`(`ENTERING`, `LOCKED_WAVES`, `CLEARED`, `TRANSITION`)는 유지한다. 스테이지 전환은 룸 상태가 아니라 **그 위 단계**이므로, 별도 플래그 또는 `StageState`(`PLAYING` / `STAGE_CLEARED` / `STAGE_TRANSITION`)로 제어한다.
- 스테이지 클리어 정비 중에는 전투·스폰·피해·출구 이동을 차단한다 (rules §6 일시정지 원인 중첩 규칙 적용).
- 승리는 **최종 스테이지 보스 처치에서만** 한 번 확정한다. 중간 스테이지 보스 처치는 승리 화면을 띄우지 않는다.

### 2.3 유지되는 것 / 초기화되는 것

| 룸 이동·스테이지 전환 모두 유지 | 스테이지 전환 시 초기화 |
| --- | --- |
| 본체 체력(§4.3 회복 규칙 적용), 보유·출전 유닛, 배치, 강화, 재화 | 격자 맵, 방 클리어/방문 기록, 활성 적·탄환, 예약 스폰, 룸별 보상 수령 정보 |

## 3. 스테이지 구성

### 3.1 기본 안: 5 스테이지

| 스테이지 | 격자(M×N) | 방 수 | 테마 | 신규 적 도입 | 보스 컨셉 | 권장 유닛 티어 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 3×3 | 6~7 | 숲 | 기본 추적형 | 숲의 수호자 (돌진) | T1 중심 |
| 2 | 3×4 | 8~9 | 늪/습지 | 원거리 사격형 | 독 늪의 군주 (독 장판) | T1~T2 |
| 3 | 4×4 | 10~11 | 화산 | 고속 돌격형, 폭발형 | 용암 거신 (범위 낙하) | T2~T3 |
| 4 | 4×5 | 12~13 | 빙하 | 방어형(느림/고체력), 소환형 | 서리 여왕 (감속장, 소환) | T3 |
| 5 | 5×5 | 14~15 | 황혼 성채 | 모든 유형 혼합, 정예 빈도 증가 | 최종 보스 (다단 페이즈) | T3~T4 |

- 스테이지 수·격자 크기는 `StageDef` 데이터로만 정의해 추가/삭제가 코드 변경 없이 가능하게 한다.
- 스테이지별 테마(타일·배경 팔레트)는 기존 픽셀 판타지 스타일(`fantasyTheme.ts`)의 팔레트 교체로 처리해 아트 비용을 줄인다.
- 방 타입 배분: 스테이지당 `SHOP` 1개, `RECOVERY` 1개, `ELITE`는 스테이지가 오를수록 증가, `BOSS` 1개. 시작 방에서 보스 방까지 도달 가능해야 하며 격자 불변식(스킬 §1.3)을 그대로 적용한다.
- 맵은 스테이지 진입 시 새로 생성한다. 시드 기반 재현은 기본 범위에 포함하지 않는다.

### 3.2 스테이지 내부 난이도 곡선

스테이지 안에서도 시작 방보다 보스 방에 가까울수록 약간 강해지게 한다 (`depth` = 시작 방으로부터의 거리 / 보스까지의 최대 거리, 0~1). 방 안에서는 웨이브 번호에 따라 소폭 증가한다.

## 4. 난이도 스케일링

### 4.1 일반 적 배율

스테이지 `s`(1부터)에 대해 **지수 곡선 + 상한**을 사용한다. 선형만 쓰면 후반이 쉬워지고 순수 지수는 급격히 불가능해지기 때문이다.

| 항목 | 제안 공식 | 비고 |
| --- | --- | --- |
| 체력 | `1 + 0.45 × (s-1)^1.15` | 가장 큰 증가 |
| 공격력(접촉 피해) | `1 + 0.25 × (s-1)` | 본체 생존 압박 |
| 이동속도 | `min(1 + 0.06 × (s-1), 1.3)` | **상한 1.3** — 조이스틱 회피 불가 방지 |
| 웨이브 수 보너스 | `floor((s-1) / 2)` | 2스테이지마다 +1 웨이브 |
| 스폰 간격 | `max(1 - 0.07 × (s-1), 0.6)` | **하한 0.6** — 풀 고갈 방지 |
| 동시 활성 적 | `min(기본 + 4×(s-1), 풀 한도의 80%)` | 풀 한도 내로 제한 |

방 내부 보정: `× (1 + 0.04 × depth × 10)`, 웨이브 n번째마다 `× (1 + 0.05 × (n-1))` 정도로 소폭 가산한다. 정예는 일반 적 배율에 `elite 배율`을 추가로 곱한다.

### 4.2 보스 스케일링

보스는 수치만 올리지 않고 **패턴·페이즈**가 스테이지마다 달라지게 한다.

| 요소 | 규칙 |
| --- | --- |
| 체력 | 일반 적 체력 배율보다 높은 별도 `bossHpMult`. 스테이지 1 보스는 "몇 번 죽어도 이길 수 있는" 수준 |
| 페이즈 | 스테이지 1~2: 1페이즈(+체력 50% 이하 시 강화), 3~4: 2페이즈, 5: 3페이즈 |
| 패턴 | 스테이지마다 고유 패턴 1~2개 추가 (돌진, 장판, 탄막, 소환). 이전 스테이지 보스 패턴을 일부 계승해 학습 곡선 유지 |
| 소환 | 보스 룸에서 쫄 소환 시 풀 고갈 규칙(스킬 §3.2)을 따르고 필수 소환은 대기열로 관리 |
| 예고 | 강한 패턴은 반드시 시각적 예고 시간(0.6초 이상)을 둔다 — 터치 조작에서의 공정성 |

보스는 한 번만 사망 처리되고(스킬 §3.2), 사망 시 남은 탄환·장판·소환 적이 정리된다. 기존 풀을 확장해 보스 전용 풀을 중복 생성하지 않는다.

### 4.3 플레이어 측 성장과의 균형

난이도는 적 곡선만으로 결정되지 않는다. **적 곡선과 플레이어 전투력 곡선의 격차**가 체감 난이도다.

- **스테이지 보상:** 스테이지 클리어 시 큰 재화 보너스 + 확정 소환 1회(또는 재료 선택). 이 값은 "그 스테이지의 일반 방 수입 합계의 일정 비율"로 정의해 경제 곡선과 연동한다.
- **재화 수입:** 방 클리어 재화는 `rewardMult`로 스테이지에 비례 증가시키되, 적 체력 증가율보다 약간 낮게 유지해 후반에 유닛 조합의 필요성이 커지게 한다.
- **티어 가용성:** 상점과 보상에서 T3 이상 재료는 스테이지 3 이후에 등장하게 제한해 유닛 도감 확장(`unit_roster_design.md`)과 진행 속도를 맞춘다.
- **회복:** 스테이지 전환 시 본체 체력을 일정 비율(제안: 최대 체력의 40%, 최대 100%까지) 회복한다. 전부 회복하면 `RECOVERY` 방의 가치가 낮아지고, 회복이 없으면 후반 누적 피해로 진행이 불가능해진다.
- **보유 한도:** 보유 16기·출전 6기는 유지한다. 스테이지가 늘면 한도가 병목이 되므로 판매/분해(`unit_roster_design.md` §1.2)를 스테이지 4 이전에 함께 구현하는 것을 권장한다.

### 4.4 밸런스 점검 기준

각 스테이지 보스 처치 시점의 목표(실측으로 조정):

| 스테이지 | 목표 조합 상태 | 목표 도달 시간 |
| --- | --- | --- |
| 1 | T1 4~6기 | 5~8분 |
| 2 | T2 1~2기 포함 | 6~9분 |
| 3 | T2 다수, T3 1기 | 7~10분 |
| 4 | T3 2~3기 | 8~11분 |
| 5 | T3 다수, T4 도전 | 10~14분 |

전체 한 런은 **대략 35~50분**을 목표로 한다. 모바일 세션을 고려해 **스테이지 전환 지점에서 저장·중단**이 가능하도록 런 저장/복원(스킬 §5의 미구현 확장)을 우선순위 높게 검토한다.

## 5. 스테이지 전환 연출·UI

- **스테이지 시작 배너:** "STAGE n — 테마명" 표시, 신규 적 종류 예고(아이콘).
- **HUD:** 현재 스테이지 번호, 보스까지 남은 방 거리 또는 미니맵의 스테이지 표시.
- **스테이지 클리어 화면:** 보상 요약(재화, 확정 소환), 정비 진입 버튼, 다음 스테이지 테마 미리보기.
- **게임 오버 화면:** 도달 스테이지·처치한 보스 수를 통계에 추가한다.
- 전환 연출(페이드)은 가볍게 유지하고 전환 중 입력을 차단한다.

## 6. 불변식 (구현 시 확인)

- 스테이지 클리어/보스 처치 보상은 **한 번만** 지급한다. 연타·씬 재진입에도 중복 지급 금지.
- 스테이지 전환은 **한 번만** 실행한다. 전환 중 지연 콜백이 이전 스테이지의 방·적·타이머를 변경하지 못하게 한다.
- 전환 시 탄환, 적, 보스 패턴 오브젝트, 예약 스폰, 장판 효과를 모두 풀로 반환하고 렌더·물리를 비활성화한다. 재활성화 시 이전 스테이지의 배율·디버프가 남지 않아야 한다.
- 적 스탯은 **스폰 시점에** 현재 스테이지 배율로 결정하며, 풀 객체 재사용 시 이전 값으로 초기화한다.
- 승리는 **최종 스테이지 보스 처치 후에만** 한 번 확정한다. 패배/승리 확정 후 피해·방 이동·스테이지 전환을 차단한다.
- 스테이지 전환 후에도 소모된 재료 유닛이 복원되지 않아야 하며, 보유 목록과 배치 상태가 일치해야 한다.
- 속도·스폰 간격 배율은 상한/하한을 코드로 강제한다 (후반 스테이지 이동속도 폭주, 풀 고갈 방지).

## 7. 검증 시나리오

| 변경 영역 | 통과 조건 |
| --- | --- |
| 스테이지 전환 | 보스 처치 → 정비 → 새 격자 진입, 이전 적·탄환 잔존 없음 |
| 중간 보스 | 승리 화면이 뜨지 않고 다음 스테이지로 이어짐 |
| 최종 보스 | 승리 화면 한 번, 통계 한 번 |
| 보상 | 스테이지 보상 연타해도 한 번만 지급 |
| 스케일링 | 스테이지 1·3·5에서 적 체력/속도/스폰 간격이 설계 값과 일치, 상한/하한 적용 |
| 풀링 | 후반 스테이지에서 풀 고갈 시 필수 스폰 대기열 동작, 탄환/효과만 생략 |
| 유지 | 스테이지 전환 후 체력(회복 규칙 적용)·유닛·재화·강화 유지 |
| 사망/재시작 | 스테이지 3에서 사망 후 재시작 시 스테이지 1·초기 유닛 2기·30 M으로 시작 |
| 앱 복귀 | 스테이지 전환/정비 중 백그라운드 전환 후에도 입력 고착·이중 전환 없음 |
| 성능 | 후반 스테이지(동시 적 최다)에서 기기/브라우저, 적·탄환 수, 관찰 시간과 함께 FPS 기록 |

## 8. 문서 반영 사항 (구현 시)

기존 문서와 충돌하는 부분은 구현할 때 함께 수정한다.

| 문서 | 수정 대상 |
| --- | --- |
| `smash_roguelike_skill.md` §1.3 | "BOSS는 최종 전투와 승리" → "중간 스테이지의 BOSS는 스테이지 클리어, 최종 스테이지의 BOSS만 승리" |

## 9. 추천 진행 순서

| 단계 | 작업 | 선행 조건 |
| --- | --- | --- |
| 1 | `StageDef`/`StageScaling` 타입과 스테이지 데이터 파일 추가, 스테이지 1개짜리로 동작 변화 없이 이관 | 없음 |

| 5 | 스테이지 2~3 데이터 + 신규 적 1~2종 + 보스 패턴 1~2종 | 3 |
