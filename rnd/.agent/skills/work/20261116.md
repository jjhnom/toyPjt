# RND 게임 프로젝트 전체 소스코드 정밀 분석 및 품질 검증 요청

당신은 시니어 게임 개발자, Phaser 3 엔진 전문가, 게임 시스템 아키텍트, QA 엔지니어, 게임 디자이너의 관점에서 프로젝트를 종합적으로 검토하는 역할입니다.

## 1. 분석 대상

- GitHub: https://github.com/jjhnom/toyPjt/tree/main/rnd
- 브랜치: main 최신 커밋
- 게임: 소환사의 원정(RND)
- 기술 스택: Phaser 3, TypeScript, Vite, Capacitor Android
- 개발 방식: AI 에이전트를 활용한 1인 게임 개발
- 주요 플랫폼: Android 모바일

GitHub에 커밋된 실제 최신 코드를 기준으로 분석해 주세요.

README와 기획 문서만 읽고 평가하지 말고, 실제 소스코드와 테스트 코드까지 확인해야 합니다.

분석 전에 AGENTS.md, .agent/rules.md, 관련 Skills 및 프로젝트 구조를 확인하고, 실제 구현이 문서의 설명과 일치하는지 검증해 주세요.

**이번 요청의 목적은 코드를 수정하는 것이 아니라 현재 프로젝트의 문제점과 개선 방향을 정확히 진단하는 것입니다.**

## 2. 전체 프로젝트 아키텍처 분석

아래 항목을 검토해 주세요.

- 디렉터리 및 모듈 구조가 적절한지
- Scene, Entity, Component, System 간 역할 분리가 적절한지
- GameScene 등 특정 파일에 기능이 과도하게 집중되어 있는지
- 순환 참조, 중복 코드, 불필요한 의존성이 존재하는지
- 현재 구조에서 신규 보스, 유닛, 스테이지, 스킬 추가가 쉬운지
- 하드코딩으로 인해 확장성이 떨어지는 부분이 있는지
- AI가 기능을 반복 추가하면서 만들어진 임시 코드나 사용하지 않는 기능이 있는지
- 기존 기능과 충돌하지 않고 리팩터링할 수 있는 구조인지

문제별로 파일 경로, 함수명, 가능하면 정확한 코드 라인을 제시해 주세요.

## 3. 실제 게임 기능 및 로직 검증

게임의 주요 시스템을 빠짐없이 분석해 주세요.

**전투 시스템**
- 플레이어, 소환 유닛, 적의 공격 및 피해 계산
- 탄환 충돌, 범위 공격, 관통, 연쇄 공격
- 스킬 쿨타임과 상태이상 중복 처리
- 적 사망 및 보상 중복 지급
- 스테이지 진행과 웨이브 종료 조건

**소환 및 성장 시스템**
- 소환 확률 및 비용
- 조합, 승급, 각성 처리
- 재화 차감 및 중복 구매 방지
- 유닛 스탯과 성장 밸런스
- 강화, 유물, 영구 성장 효과의 중첩

**보스 시스템**
- 보스별 AI와 공격 패턴
- 공격 예고와 실제 피해 범위 일치 여부
- 스킬 중복 발동 및 비정상 종료 가능성
- 보스 페이즈 전환의 정상 동작 여부
- 보스마다 충분한 전투 차별성이 존재하는지
- 스킬 이펙트, 피격 효과, 사운드, 카메라 연출의 부족한 부분

**저장 및 복구 시스템**
- 자동 저장과 이어하기
- 앱 강제 종료 시 데이터 손실 가능성
- 기존 버전 저장 데이터 호환성
- 저장 중 실패, 데이터 손상, 중복 보상 문제
- 신규 콘텐츠 추가 시 기존 저장 데이터에 미치는 영향

각 기능에 대해 구현 상태, 정상 동작 여부, 예상 오류, 추가 테스트 필요 여부를 구분해 주세요.

## 4. 버그 및 잠재적인 오류 검증

단순한 코드 스타일 검토가 아니라 실제 게임에서 발생할 가능성이 있는 오류를 찾아주세요.

특히 다음 상황을 집중적으로 검증해 주세요.

- 적이나 탄환이 대량 생성되는 경우
- 오브젝트 풀이 가득 찬 경우
- 보스 스킬이 동시에 여러 개 발동하는 경우
- 몬스터 사망과 보상 지급이 동시에 처리되는 경우
- 게임 일시정지 및 재개
- 앱 백그라운드 전환 및 복귀
- 전투 중 화면 터치 취소 및 멀티터치
- 스테이지 전환 중 저장과 종료
- 신규 게임 시작 및 기존 게임 재개 반복
- 같은 씬을 여러 번 생성하거나 종료하는 경우
- 이벤트 리스너, 타이머, 객체가 정상적으로 해제되지 않는 경우

실제로 확인한 버그와 코드 분석상 추정되는 위험은 반드시 구분해 주세요.

## 5. Android 모바일 성능 및 메모리 분석

모바일 게임 기준으로 다음을 검토해 주세요.

- 매 프레임 불필요하게 실행되는 코드
- 반복적인 객체 생성 및 메모리 할당
- 불필요한 Graphics 렌더링
- 파티클 및 스킬 이펙트의 GPU 부하
- 오브젝트 풀 재사용과 초기화 오류
- 적이 대량 등장했을 때 충돌 검사 비용
- 텍스처 및 스프라이트 아틀라스 최적화
- 메모리 누수 및 장시간 실행 시 성능 저하 위험
- 로딩 시간과 APK 용량 개선 여지
- 모바일 해상도, 화면 비율, 노치, 시스템 제스처 대응

최적화가 필요한 부분은 현재 방식과 권장 방식을 비교하고, **FPS 및 메모리 개선 가능성**을 설명해 주세요.

실제 측정하지 않은 성능 수치를 사실처럼 제시하지 마세요.

## 6. 게임 디자인과 완성도 평가

코드 구현 수준뿐 아니라 실제 유저가 플레이하는 게임이라는 관점에서 평가해 주세요.

- 전투가 반복적이거나 단조롭지 않은지
- 일반 몬스터와 보스의 전투 경험이 충분히 차별화되는지
- 스킬의 시각적 타격감과 피드백이 부족하지 않은지
- 소환·조합·성장에 전략적 선택의 재미가 있는지
- 신규 유닛이나 스킬이 기존 콘텐츠와 충분히 차별화되는지
- 초반·중반·후반 난이도와 성장 속도가 적절한지
- UI/HUD 가독성과 조작 편의성이 충분한지
- 사운드, BGM, 애니메이션, 전환 연출이 부족하지 않은지
- 유저에게 목표와 보상이 명확하게 전달되는지

현재 구현된 기능 중 완성도를 높여야 할 부분과, 게임성을 강화하기 위해 추가하면 좋은 기능을 따로 제안해 주세요.

특히 **보스 스킬 이펙트와 타격감, 스킬 차별화, 모바일 전투 연출**을 중점적으로 평가해 주세요.

## 7. 테스트 실행 및 자동화 검증

실행 환경이 지원된다면 다음 명령어를 실행해 주세요.

```bash
npm ci
npm test
npm run build
```

브라우저 테스트와 통합 테스트도 실제 실행 조건을 확인하고 가능한 범위에서 검증해 주세요.

추가로 다음을 확인해 주세요.

- 기존 테스트가 주요 게임 로직을 충분히 검증하는지
- 테스트가 빠져 있는 기능은 무엇인지
- 정상 시나리오만 검증하고 예외 상황은 누락하지 않았는지
- GitHub Actions에서 자동 검증이 충분히 이루어지는지
- 신규 기능을 추가해도 기존 기능을 보호할 수 있는지
- Android 실기기에서 추가 검증해야 할 항목은 무엇인지

실행하지 못한 테스트는 성공으로 표시하지 말고, 미실행 이유를 설명해 주세요.

## 8. 부족한 기능 및 추가 개발 제안

현재 게임에 실제로 없는 기능과, 구현되어 있지만 보완이 필요한 기능을 구분해 주세요.

다음 관점에서 제안해 주세요.

1. 현재 게임의 품질을 위해 반드시 필요한 기능
2. 게임의 재미와 몰입도를 높이는 기능
3. 유지보수와 신규 콘텐츠 확장을 쉽게 만드는 기능
4. 모바일 성능과 안정성을 강화하는 기능
5. 정식 출시 전 반드시 준비해야 할 기능

기능을 추가했을 때 기존 시스템과 충돌할 위험도 함께 분석해 주세요.

새로운 기능을 무조건 많이 제안하기보다 **현재 프로젝트에 가장 큰 효과를 줄 수 있는 개선 사항**을 우선해 주세요.
