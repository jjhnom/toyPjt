# 로드맵 2단계 — 킬 보상 곡선 선택

상태: 제곱근 배율 승인·적용·검증 완료. 2026-11-06 사용자 응답: “제곱근 배율 적용 — 완만하게 감소 (추천)”.

## 변경 전 동작

적 종류별 `mineralValue`에 `rewardMult = 1 + 0.3 * stageIndex`를 곱하고 매 처치마다 반올림한다. 스테이지가 진행될수록 맵 크기·방 수·웨이브 수·적 종류도 증가한다. 방/보스 클리어 재화는 별도다.

## 같은 조건의 비교

`npm run economy:report -- 42` 결과. 모든 방 클리어, 소환진 SAFE, 필수 스폰 전부 처치, 보스 호위는 보스보다 먼저 처치한다. 전투 시간에 따른 추가 소환과 실제 플레이는 포함하지 않는 모델이다. 아래는 **스테이지당 유입 재화**이며 초기 자금과 지출을 포함하지 않는다.

| UI 스테이지 | 변경 전 선형 배율 | 적용한 제곱근 배율 | 킬 배율 제거 |
| --- | ---: | ---: | ---: |
| 1 | 618 | 618 | 618 |
| 2 | 1,269 | 1,197 | 1,079 |
| 3 | 3,209 | 2,670 | 2,246 |
| 4 | 6,375 | 4,909 | 3,809 |

같은 시드의 최단 보스 경로에서 5스테이지 유입은 각각 2,970 / 2,214 / 1,707이다. 탐험 경로가 수입에 미치는 영향이 크므로 전체 탐험 값만 보고 비용을 올리지 않는다.

## 승인한 변경

적용한 안은 **제곱근 배율**이다. `round(mineralValue * sqrt(rewardMult))`로 매 처치의 반올림을 유지한다. 1스테이지는 그대로이고 변경 전 대비 5스테이지 전체 수입을 모델상 약 28.7% 줄인다. 배율 완전 제거는 같은 조건에서 약 47.9% 줄여 초기 변경으로는 폭이 크다.

이는 실제 재미·난이도나 적정 잔액이 검증되었다는 뜻이 아니다. 게임 규칙 변경은 실제 킬 보상 함수의 기본 정책에 한정한다. 방/보스 클리어 보상·적 수/능력치·제작 가격·보유/출전 한도는 유지한다. 보스 적 자체의 킬 재화에도 제곱근 배율을 적용하고, 별도의 스테이지 클리어 보상은 유지한다. 저장된 잔액을 소급해 차감하지 않는다.

실제 정책은 `LIVE_KILL_REWARD_POLICY = 'sqrt'`다. 분석용 기존 선형 정책은 `current`에서 `linear`로 명칭을 바꿔 실제 게임 정책과 혼동하지 않도록 했고, 시뮬레이터 기본값도 실제 정책을 따른다. 명시적 `linear`/`sqrt`/`unscaled` 비교는 계속 지원한다.

검증: 모든 적 종류의 1~5스테이지 킬 보상·기존 방 보상을 검사한다. 시드 0/1/42/100/4294967295의 전체 탐험·최단 보스 경로에서 스테이지별 고정 목표 제작과 잔액·정원 준수를 확인했다. v1 저장 잔액 819 및 소환권 3장은 그대로 복원하고 이후 바위 골렘 킬에만 새 보상 21을 더하는 호환 테스트를 추가했다. 기존 회귀 포함 모델 테스트 69개와 strict TypeScript/Vite 빌드가 통과했다.

Chrome 156에서 `node tests/kill-reward-browser.mjs`로 실제 GameScene의 1~5스테이지 처치→지급→로그→방 클리어→저장 잔액을 확인했다. SWARMER는 4/5/5/6/6, ELITE_BRUTE는 32/36/40/44/47을 지급하며 일반 방 클리어 보상 25/33/40/48/55는 유지된다. `node tests/browser-smoke.mjs`의 소환·조합·편성·일시정지·스테이지 전환·이어하기 전체 회귀도 통과했다. 초기 페이지 로딩 시간 초과 1회 후 새 브라우저에서 재실행해 통과했다. 실제 인간 플레이 밸런스와 Android 실기기 검증은 별도다.

롤백: 실제 킬 보상 기본 정책을 `linear`로 되돌린다. 저장 형식 변경은 필요 없다.
