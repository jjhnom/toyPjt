# 최대 편성·BGM·전투음·보스 VFX 동시 부하 — 2026-11-19

## 결과

소환 유닛 6기(본체를 포함하면 아군 7기), 적 64기, 탄환 목표 160개, 서리 여왕 장판·연속 폭격을 동시에 실행했다. 오디오 끔/전투 BGM/보스 BGM 비교 18회와 BGM 전환 중 부하 2회를 완료했다.

이 PC에서는 **약 60 FPS, 프레임 시간 p95 16.8~16.9ms**를 유지했다. 효과음은 8음성 상한에 도달했으며 오디오 오류·unlock 실패·실행 중 컨텍스트 중단은 없었다. 오디오 활성 조건에서 서리 여왕 충격음 556회 요청이 모두 재생 처리됐다. 종료 후 효과음 음성·BGM 트랙·보스 VFX·탄환·적의 활성 수는 모두 0이었다.

게임 코드·볼륨 기본값·밸런스·풀 크기는 변경하지 않았다. PC 합성 부하에서의 결과이며 실기기 성능·모든 편성의 최악 부하·청감 품질을 보장하지 않는다.

## 환경과 장면

- Windows, Intel Iris Xe / ANGLE Direct3D11, Headless Chrome 157.0.8103.79. 실제 WebGL 렌더러를 확인하고 SwiftShader 등 소프트웨어 렌더러이면 실패 처리한다.
- 모바일 에뮬레이션 720×1280, DPR 1, Vite 개발 서버. 프레임 계측 중 단위 테스트·빌드를 실행하지 않았다.
- 실제 `SQUAD_LIMITS.deployed=6`을 확인했다. 모든 소환 유닛은 최대 3성이며 6개 출전 슬롯을 채운다. 최고 등급 편성은 실제 타입 설정의 4티어도 확인했다.
- 전투 장면은 기존 공유 fixture를 사용했다. 적 64기 중 서리 여왕 1기, 나머지 TANK. 자연 AI·유닛별 사격·탄환 적중·충돌·피해 효과를 실행한다. 예약 스폰·자동 보스 패턴은 막고 기존 연속 폭격 계획 10개와 별도 서리 장판 2개를 3.2초마다 추가했다.
- 적·아군 체력을 높이고 아군을 무적 처리해 개체 수를 유지했다. 탄환은 기존 풀로 보충하고 초과분을 정리한다. 목표 160개는 `postupdate` 보충 직후 수이며 물리 처리 중 순간 활성 수와 다를 수 있다.
- 오디오는 실제 입력으로 해제하고 샘플 41개 decode 완료를 확인했다. native HTML5Audio BGM과 Web Audio 전투·보스 효과음을 실행했다. master=1, sfx=1, 음악 배율=1. 기존 트랙 설정 전투 .17, 보스 .15를 사용한다. 실제 스테이지 진행 규칙을 바꾼 것은 아니다.

## 측정 방법과 프레임 결과

기본 조건마다 1.2초 준비 후 10초 관찰했다. 각 편성에서 오디오 끔→전투 BGM→보스 BGM을 실행하고 역순으로 반복했다. 혼합·최고 등급 편성에는 각각 15초 관찰 중 2.5초마다 BGM을 바꾸는 조건도 추가했다. 고부하 관찰 시간 합계는 약 210초다.

RAF 간격으로 평균 FPS와 nearest-rank p95를 구했다. 메인 스레드 p95는 `prestep`~`postrender` 경과 시간으로 렌더 제출과 계측 오버헤드를 포함한다. GPU 완료 시간이나 별도 오디오 스레드 CPU 시간은 아니다. 각 행은 두 번의 기본 실행에서의 범위다. BGM 전환 행은 1회씩이다.

## 오디오 동작과 믹싱

- 100ms마다 BGM의 실제 HTMLAudioElement가 준비 상태이고 pause/error 없이 재생 중인지, `currentTime`이 진행하는지 확인했다. 전투음 활성 조건에서 Web Audio 컨텍스트는 모든 관찰 시점에 running이었다. 단순 재생 요청 카운터만으로 소리가 실행됐다고 판정하지 않았다.
- 전환 조건마다 BGM 전환 6회, 순간 최대 트랙 2개를 확인했다. 음악 오류는 0이었다.
- 전투음의 요청 ID와 실제 재생 처리 ID를 기록했다. 오디오 활성 조건에서 서리 여왕 충격음은 **556/556회 재생 처리**됐다. 비활성 대조군의 요청 222회는 의도적으로 재생하지 않았다. 경고음은 장판/폭격이 같은 시점에 요청하면서 기존 쿨다운으로 중복이 합쳐졌다.
- 일반 전투음에는 쿨다운·음성 제한에 따른 생략이 있었다. 기본 활성 조건 1회(준비 포함 약 11.2초)당 실제 재생 처리 221~242회, 쿨다운 생략 2,983~4,065회, 음성 제한 생략 929~1,207회였다. 높은 충돌·피해 요청을 만드는 합성 부하에서 기존 정책이 작동한 결과이며 오디오 오류와 구분한다. 체감상 효과음 밀도가 적절한지는 별도 청감 판단이 필요하다.
- SFX는 기존 출력 guard 뒤에 analyser를 분기하고 무음 출력으로 연결했다. 원래 출력 경로는 유지하며 종료 시 분기를 해제한다. 100ms마다 2,048개 샘플을 읽은 범위에서 피크 최대 **.6964**, 절댓값 1 이상 샘플은 0이었다. 연속 전체 샘플을 녹음한 검사나 HTML5Audio BGM을 합친 실제 출력 캡처는 아니다.
- 별도 기존 `audio-mix-browser` 회귀도 실행했다. 실제 admitted SFX를 재구성하는 combat-barrage/eight-voice-burst와 BGM 3곡·위치 3개·guard 유무를 조합한 **36회 OfflineAudioContext 렌더**가 통과했다. guard 적용 조합의 최악 피크 **.7814887**, clipped sample 0이었다. 이 검사는 새 최대 편성 20조건의 전체 오디오를 그대로 녹음한 결과와 구분한다.

## 남은 범위와 다음 작업
