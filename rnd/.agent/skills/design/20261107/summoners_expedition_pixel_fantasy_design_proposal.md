## 1. 이번에 확정할 디자인 방향

**‘보랏빛 마법 세계에서, 작은 픽셀 동료를 모아 원정하는 게임’**을 시각적 중심으로 제안한다.

이전 019의 카툰 벡터 전환 제안 대신 **픽셀 판타지를 최종 스타일로 유지**한다. 기존 캐릭터와 던전의 정체성을 살리면서 복잡한 금속 장식은 정리하고, 제목·버튼·보상에 보라색과 금색을 집중한다. 전투는 캐릭터·탄환·위험 예고가 우선이고, 정비는 재료·결과·출전 상태가 우선이다.

수정 가이드의 ‘기존 팔레트 유지’와 이미지의 ‘보라·금색 강화’는 다음처럼 결합한다.

- **전투·본문의 바탕:** 현재의 어두운 잉크·슬레이트를 유지해 읽기 편하게 한다.
- **세계관과 강조 면:** 타이틀, 제목 리본, 선택 카드, 보조 버튼에 보라색 계열을 확장한다.
- **주요 행동과 특별 보상:** 금색을 사용한다. 일반 패널마다 강한 금색 장식을 반복하지 않는다.
- **캐릭터·효과:** 픽셀 윤곽을 유지하고, 효과는 짧은 밝은 코어와 속성 실루엣으로 구분한다.

## 2. 참고 목업과 적용 원칙

![수정된 픽셀 판타지 디자인 가이드와 5개 화면 목업](<소환사의 원정 픽셀 아트 디자인 가이드.png>)

이미지는 **시각 목표를 제시하는 참고 목업**이다. 표시된 기능·가격·보상·통계가 현재 게임의 구현이나 확정 규칙을 의미하지 않는다. 원본 영상은 제공되지 않아 영상의 장면·효과 타이밍을 직접 확인한 것으로 기록하지 않는다.

현재 디자인 폴더에서 확인한 사용자 원본은 수정 MD와 PNG 두 파일이다. 이전 `visual_ui_design_system_mockup_preview.html`은 현재 파일이 없으므로 이번 기획의 근거로 사용하지 않는다.

### 이미지에서 채택할 요소

| 요소 | 채택 방향 |
| --- | --- |
| 보라색 밤하늘·성·수정 | 타이틀과 배경 장식의 분위기로 활용 |
| 작은 픽셀 소환사·동료 | 큰 얼굴·무기·역할 실루엣으로 읽히는 비율을 참고 |
| 금색 주요 버튼·보라색 보조 버튼 | 행동 위계를 공통 컴포넌트로 적용 |

## 3. 현행 구현과 충돌하지 않아야 할 기준

- 지정 소환 → 재료 확보 → 고정/조건 레시피 조합 → 출전 편성 → 다음 방의 흐름을 유지한다.
- 22종 유닛, 보유 16기·출전 6기, 기존 Tier·별·각성·판매·간편 제작 규칙을 유지한다.
- 스토리 5개 스테이지뿐 아니라 S6 이후 무한 원정·종료/계속 선택도 디자인 범위에 포함한다.
- 저장은 스테이지 시작만이 아니라 방 보상·정비 거래 등의 v2 안전 지점을 사용한다. 화면 안내를 옛 정책으로 축소하지 않는다.
- `SquadScene`을 주 정비·보상 흐름으로 유지한다. `RewardScene`을 중심 화면으로 되돌리지 않는다.
- 본체 HP, 동료별 HP·전투 불능·부활·보호막, 현재 클래스 액티브와 쿨다운을 구분한다.
- `FOREST/WIND/FIRE/FROST/LIGHTNING/EARTH/SHADOW/LIGHT`의 실제 표시명은 **숲/바람/불/서리/번개/대지/암흑/빛**을 사용한다. 독·비전 표현을 새 속성으로 추가하지 않는다.
- 새 UI가 거래 확정·저장·피해 판정의 원천이 되지 않게 한다. 원천 데이터는 기존 시스템을 따른다.

## 4. 아트·픽셀 표현 규격

### 캐릭터와 배경

- 기존 소환사·유닛 아트를 우선 재사용한다. 첨부 이미지의 캐릭터 수가 전체 유닛 수를 대신하지 않는다.
- 아군은 얼굴·장비·역할 실루엣, 적은 몸체·공격 자세·바닥 위험 도형으로 구별한다. 속성 색만으로 적아를 구분하지 않는다.
- 새 아트가 필요하면 소환사·숲의 사수·석재 방패병·약초 사제·기본 적을 대표 샘플로 검토한 뒤 확장한다.
- 배경은 중심부 저대비, 벽·가장자리에 장식을 배치한다. 타이틀의 밝은 성·수정을 전투 바닥에 같은 밝기로 반복하지 않는다.
- 로고·아이콘·개별 스프라이트는 게임용 별도 자산으로 준비한다. 전체 안내 PNG를 잘라 최종 게임 에셋으로 바로 쓰지 않는다.

### 픽셀과 텍스트

- 현재 `pixelArt: true`, `roundPixels: true`를 유지한다. 픽셀 텍스처는 NEAREST 계열 필터링을 기준으로 확인한다.
- 아트 제작 격자와 실제 출력 크기를 구분한다. 현재 유닛 아틀라스 셀은 128×128이므로 전체 에셋을 임의로 16×16·32×32로 재규격화하지 않는다.
- 전투 표시 크기·바디·오프셋·좌우 반전·애니메이션 키를 보존한다. 이펙트가 커졌다고 공격 범위가 커진 것처럼 보이지 않게 한다.
- UI 프레임은 계단형 모서리와 2~3단 명암을 기본으로 한다. 긴 패널에서 모서리 장식이 늘어나지 않도록 분할 가능한 프레임을 준비한다.
- 한글 본문은 읽기 쉬운 산세리프를 유지한다. 픽셀 폰트는 제목·짧은 숫자 샘플에서 먼저 검토하며, 새 폰트 파일·한글 범위·라이선스 확인 전 도입하지 않는다.
- 게임 내부 배치를 픽셀 격자에 맞춰도 FIT 출력 배율이 비정수이면 도트 크기가 균일하지 않을 수 있다. 360·320·412 폭에서 실제 출력 품질을 확인한다.

## 6. 레이아웃·문자·터치 규격

- 기준 판은 **720×1280 GU(게임 좌표)**다. 실제 출력은 CSS px로 확인한다.
- FIT 배율은 `s = min(표시 가능 너비/720, 표시 가능 높이/1280)`, 표시 크기는 `GU × s`다. 360×640에서는 `s=0.5`다.
- 기본 바깥 여백 24 GU, 내부 간격 8/16/24/32 GU, 프레임 모서리는 4/8 GU 격자를 기준으로 시안을 비교한다.
- 화면 제목 40~48 GU, 카드 제목 32 GU, 본문 28~30 GU, 보조 설명 24~26 GU를 시작값으로 한다. 360 폭의 주요 본문은 약 14~15 CSS px다.
- 중요한 한글 설명을 작게 줄여 가로 3열에 넣지 않는다. 글자가 길면 세로 카드·다음 페이지로 나눈다.
- 터치 영역은 44×44 CSS px 이상을 목표로 하며, 기본 100×100 GU 이상에서 시작해 `ceil(44/s)` GU 이상인지 확인한다. 인접 영역을 겹치지 않는다.
- 일반 문자는 대비 4.5:1, 큰 글자·필수 경계는 3:1을 검증 목표로 둔다. 전체 화면이 검증을 마친 상태는 아니다.
- 노치·제스처·안전 여백을 제외한 실제 표시 영역으로 배율을 계산한다. 안전 여백을 이중 적용해 게임이 불필요하게 작아지지 않게 한다.

수정 가이드의 상단 12~16%, 중간 65~72%, 하단 16~22%는 후보 범위이며 조합에 따라 합계가 100%를 넘을 수 있다. 초기 전투 배치는 현재 경계를 우선한다.

| 구역 | 초기 기준 | 원칙 |
| --- | --- | --- |
| 상단 | 0~170 GU · 약 13.3% | 영웅·HP·진행·재화·지도 요약 |
| 전투 | 170~1090 GU · 약 71.9% | 현 전투 경계 유지 |
| 하단 | 1090~1280 GU · 약 14.8% | 이동 피드백·정비·액티브·중단 |

후속 시안에서 공간 부족이 확인되면 먼저 요약/상세를 분리한다. 시각 개선을 이유로 전투 공간과 이동 경계를 임의로 바꾸지 않는다.

## 7. 공통 UI 컴포넌트

| 컴포넌트 | 외형 | 필수 상태 |
| --- | --- | --- |
| 주요 버튼 | 금색 면·어두운 글자·짙은 아래 받침 | 기본/눌림/불가/처리 중 |
| 보조 버튼 | 보라색 면·밝은 글자 | 기본/눌림/선택/불가 |
| 일반 패널 | 어두운 본문 면·얇은 경계 | 기본/주의/저장 실패 |
| 제목 리본 | 보라색 면·작은 금색 끝 장식 | 제목·짧은 상태, 본문 전체를 장식하지 않음 |
| 유닛 카드 | 초상·이름·Tier/별·역할/속성·행동 | 소환 가능/한도/단계 제한/출전/대기/전투 불능 |
| 조합 카드 | 결과·재료 수량·소모 개체·추가 비용 | 가능/재료 부족/잔액 부족/손실 확인/실패 |
| 선택 카드 | 고유 아이콘·실제 효과·선택 행동 | 선택권 있음/없음/보유/보류 가능 |
| 피드백 띠 | 작은 아이콘·읽을 수 있는 짧은 문장 | 성공/실패/보상 대기/저장·지급 재시도 |

눌림은 시각 요소만 2~4 GU 이동하고 터치 영역은 고정한다. 비활성 이유는 색과 함께 텍스트로 표시한다. 기존 각성 소멸·보상 포기·새 모험 확인창은 유지하고 일반 거래마다 확인창을 새로 추가하지 않는다.

공통 진입점은 현재 [fantasyTheme.ts](../../../../src/ui/fantasyTheme.ts)를 유지한다. `art_frame`·`art_panel` 이미지가 있으면 해당 경로를 우선 사용하므로 토큰만 변경해서는 외형이 완성되지 않는다. 이미지 프레임·도형 폴백·Canvas/WebGL 경로를 함께 검토한다.

## 8. 5개 화면 목업을 실제 게임에 대응하는 설계

아래 M1~M5는 상세 목업의 제작 명세다. 후속 작업으로 위 HTML 목업을 제작했으며, 이는 실제 게임 구현 완료 범위를 의미하지 않는다.

### M1. 타이틀·이어하기 — PNG의 첫 번째 화면

- 상단: 로고와 현재 선택 클래스, 필요하면 영혼 조각 요약. 런 재화·스태미나처럼 보이게 표시하지 않는다.
- 중앙: 소환사와 대표 동료, 보랏빛 원정 배경. 기존 아트 재사용안을 먼저 비교한다.
- 하단: 저장이 있으면 ‘이어하기’를 우선 강조, 없으면 ‘새 모험’을 주요 행동으로 둔다. 기존 새 모험의 저장 교체 확인을 보존한다.
- 보조 행동: 영혼의 야영지·원정 도감·사운드. 미구현 로비 버튼은 만들지 않는다.
- 상태: 저장 없음/복구된 저장/저장 불가·손상/지급 대기를 실제 상태에 맞게 표시한다.

### M2. 정비·소환·조합·원정대 — PNG의 두 번째 화면

```text
원정 정비 / 현재 스테이지
◆ 마력석 · 보유 n/16 · 출전 n/6 · 소환권
최근 보상 / 거래 / 저장 상태
[동료 소환] [조합의 제단] [원정대]
선택 탭의 카드 목록 / 필터 / 페이지
[간편 제작] [성장·보상] [시설·시너지] [도감]
[현재 흐름에 맞는 정비 종료 행동]
```

- 기본 3탭과 기존 기능을 유지한다. 보조 기능 묶음은 정보 구조 제안이며 현재 진입·대기 보상 우선순위를 먼저 확인한다.
- 소환 카드: 실제 유닛 이름·초상·역할·속성·핵심 스킬, 적용될 비용 또는 소환권, 불가 이유를 표시한다.
- 조합 카드: **결과 → 재료 보유/필요 → 실제 소모 개체 → 추가 비용 → 조합** 순서로 보여준다. 이미지의 장식 화살표는 실제 재료와 결과 사이에만 사용한다.
- 조건 조합에는 후보 유닛·수량을, 승급에는 Tier와 별을 구분해 표시한다. ★·각성·출전 유닛 소모 주의와 기존 확인 흐름을 유지한다.
- 원정대: 6칸 출전 요약과 전체 보유 목록, HP·전투 불능·대기·시너지를 구분한다. 기존 버튼 편성을 유지하고 드래그 배치 규칙은 추가하지 않는다.
- 페이지당 카드 수는 큰 글자·터치 영역을 기준으로 정한다. 16기 전부를 작은 아이콘으로 한 화면에 강제하지 않는다.
- ‘다음 방’과 ‘다음 스테이지’는 현재 종료 콜백과 `closeLabel`에 맞게 구분한다.

### M3. 전투 — PNG의 세 번째 화면, 최우선 적용 대상

- 상단 고정: 본체 HP·현재 클래스/Lv·XP, 실제 스테이지/방·웨이브, 재화·미니맵을 표시한다.
- 동료 6칸: HP·전투 불능·부활 대기·스킬 상태를 요약한다. 작은 초상에 충분한 터치 영역이 안 나오면 큰 상세 진입점에서 선택하는 안을 비교한다. 상세 열람 중 전투가 계속되는 현재 동작은 문구로 알린다.
- 보스: 현재 보스는 머리 위 HP 표시가 있다. 별도의 상단 보스 HP·이름·페이즈는 **추가할 읽기 전용 UI 제안**이며 기존 구현으로 보고하지 않는다. 보스 때 상단 보조 줄을 교체하는 안을 우선 검토해 세 번째 줄이 전장을 덮지 않게 한다.
- 보스 등장 배너와 패턴 전조는 구분한다. 수정 가이드의 ‘진입 0.8초’를 모든 공격의 예고 시간으로 적용하지 않는다. 현재 보스별 패턴 예고는 1~1.1초이며 그 시간을 유지한다.
- 하단: 동적 조이스틱, 현재 클래스 액티브, 정비, 중단·타이틀을 유지한다. 이미지처럼 여러 공격 스킬 버튼이나 새 일시정지를 추가하지 않는다.
- 조이스틱은 외형을 정리하되 실제 `pointer.y >= 160` 시작 조건·가로 범위·포인터 소유를 임의로 축소하지 않는다. 버튼 터치가 이동에 전파되지 않게 한다.
- 작은 화면에서도 캐릭터·적·위험 도형이 피해 숫자와 장식에 가려지지 않아야 한다.

### M4. 재능·유물 선택 — PNG의 네 번째 화면

- 모바일 기본은 가로로 긴 카드 3개를 세로 배치한다. 이미지의 가로 3열 분위기는 큰 아이콘·테두리·선택 강조에 반영한다.
- 재능은 현재 ‘분대 지휘/소환사의 활력/회복 집중’을 사용한다. 3레벨마다 쌓이는 선택권·반복 선택·보류를 유지한다.
- 유물은 기존 고유 효과·보유 상태·미수령 보상을 사용한다. ‘별 개수’로 새로운 희귀도를 부여하지 않는다.
- 유료 새로고침·무작위 옵션을 추가하지 않는다. 기존처럼 선택 즉시 반영하는 흐름에서는 별도 이중 확정도 추가하지 않는다.
- 선택 모달에서는 기존 전투·스폰·피해·타이머·이동 정지를 보존한다. 조이스틱이 활성 상태로 보이지 않게 한다.
- 소환진 안전 회수/도전/지나가기와 무한 종료/계속·변이 선택에도 공통 카드 표현을 확장한다.

### M5. 스테이지 완료 요약·최종 결과 — PNG의 다섯 번째 화면

- 중간 스테이지 완료: `SquadScene` 상단에 완료 제목·이미 지급된 보상·다음 준비를 요약한다. 보상 연출을 새 지급 거래로 사용하지 않는다.
- S5 이후 종료/계속 선택은 기존 `EndlessChoiceScene`의 흐름을 유지한다. 계속을 고르면 다음 준비로, 종료를 고르면 최종 결과로 연결한다.
- 원정 종료: `GameOverScene`에서 승리/패배·도달 스테이지·정화 방·처치·토벌·남은 마력석·최종 동료를 표시한다.
- 최종 결과의 주요 행동은 기존 재도전·타이틀이다. 종료한 런에 ‘다음 스테이지’를 붙이지 않는다.
- 영혼 조각 지급/대기·재시도·저장 경고는 축하 배너 아래에서도 읽을 수 있게 유지한다.
- ‘남은 마력석’을 ‘이번에 새로 획득한 보상’처럼 표시하지 않는다. 진단용 합계나 임의 예시로 유닛별 피해 MVP를 만들어내지 않는다.

## 9. 전투 이펙트·모션 규칙

시각 중요도는 **적의 판정 예고 → 본체·아군 상태 → 실제 공격·명중 → 보상·장식** 순서다. 반짝임의 크기보다 위험 정보의 가림 여부로 판단한다.

| 효과 | 시각 후보 | 제한 |
| --- | --- | --- |
| 기본 공격 | 작은 코어·짧은 궤적, 100~200ms 피드백 후보 | 명중 판정·연사 간격 변경 없음 |
| 주요 스킬 | 속성 문양·작은 충격 링, 250~400ms 피드백 후보 | 별도 시전 지연·궁극기 시스템 추가 없음 |
| 서리 | 시안 파편·결정형 윤곽 | 보호막은 방패형으로 구분 |
| 불 | 주황 코어·어두운 적색 테두리·짧은 스파크 | 적 장판 테두리를 덮지 않음 |
| 번개 | 꺾인 선·짧은 흰 코어 | 화면 전체 반복 플래시를 기본으로 사용하지 않음 |
| 암흑/비전 느낌 | 보라 소용돌이·문양 | 기존 유닛 스킬의 외형이며 새 속성 아님 |
| 회복/보호막 | 회복은 십자·상승 입자, 보호막은 방패·경계 | 실제 HP·보호막 적용 후 피드백 |
| 보상 | 작은 반짝임·HUD 방향의 이동 | 시각 효과만 제안, 즉시 지급 정책·재화 획득 조건 변경 없음 |
| 버튼/조합 | 눌림 60~100ms, 성공 200~300ms 후보 | 확정 거래 뒤에만 성공 연출, 연출 중 연타 중복 차단 |

시간 값은 시각 연출 후보이며 현재 스킬 지속시간·피해 타이밍을 재정의하지 않는다. ‘예고→발동→잔광’ 연출이 기존 피해보다 먼저 또는 늦게 맞는 것처럼 보이지 않게 실제 이벤트에 맞춘다.

### 성능·저사양 대응

- [skillEffectTextures.ts](../../../../src/ui/skillEffectTextures.ts)는 텍스처 생성·재사용, [EffectParticlePool.ts](../../../../src/entities/EffectParticlePool.ts)는 효과 풀, [DamageTextPool.ts](../../../../src/entities/DamageTextPool.ts)는 숫자 풀을 담당한다. 역할을 분리하고 기존 풀을 확장한다.
- 현재 효과 풀 상한은 120이며 일반 burst는 활성 100개부터 추가를 멈춰 스킬 피드백용 여유를 둔다. 무조건 풀 크기를 늘리지 않는다.
- 장식 잔상·보상 반짝임·중복 피해 숫자부터 축소한다. 적 공격 예고와 필수 상태 정보를 제거하는 방식으로 부하를 줄이지 않는다.
- 수정 가이드의 자동 저사양 축소·흔들림 강도 설정은 이번 확인 범위에서 구현을 확인하지 못했다. 필요하면 별도 선택 작업으로 검토하며 기본 완료 조건에 이미 있는 기능처럼 넣지 않는다.
- 상시 블러·전면 발광·새 셰이더를 전제하지 않는다. 60 FPS는 목표이며 같은 기기·적/탄환 수·시간의 전후 측정이 필요하다.

## 10. 적용 작업과 완료 조건

수정 가이드의 P0 전투 → P1 효과 → P2 정비 → P3 타이틀/결과 우선순위를 유지한다. 공통 토큰·프레임의 대표 샘플은 P0에 필요한 만큼 먼저 정의한다.

| 단계 | 목표·대상 | 선행 조건 | 완료 조건 | 주요 위험 |
| --- | --- | --- | --- | --- |
| 준비 | M1~M5 상세 시안·기본/실패 상태, 공통 프레임·버튼 샘플 | 본 기획안 기준 정리 | 360×640에서 핵심 정보와 행동 확인, 실제 규칙 대응 | PNG에 있는 미구현 기능을 그대로 반입 |
| P0 | `GameScene`, `fantasyTheme`, 필요 아트 연결: HUD·상단 보스 HP·가림 개선 | 전투 상세 시안 | 기존 경계·HP·지도·분대·입력 유지, 보스 표시 추가가 읽기 전용 | HUD 과밀·장식 프레임 잔존 |
| P1 | `skillEffectTextures`, `EffectParticlePool`, `DamageTextPool`: 속성·명중 가독성 | P0 배치 | 예고·아군·탄환·장식 구분, 풀 상한·판정 유지 | 연출이 판정을 가림·GC/과밀 |
| P2 | `SquadScene`, `recipePresentation`: 카드·재료·출전·성장/시설 진입 | 공통 카드 규격 | 기존 모든 기능 접근, 소모·비용·실패·보류 명확 | 거래 연타·손실 경고·대기 보상 누락 |

전체 캐릭터 재제작·자동 품질 모드·새 폰트/의존성·대규모 리팩터링·새 규칙·서명/배포 변경은 이 계획의 기본 구현 범위에 포함하지 않는다. 자산 수량과 상세 시안 확인 전 전체 제작 일정을 확정하지 않는다.

## 11. 검증 시나리오와 실행 조건

### 후속 구현 때 실행할 검사

- 코드 변경 후 `npm test`, `npm run build`. 모바일 입력 변경 시 개발 서버와 Chrome 환경에서 `node tests/browser-smoke.mjs`.
- 변경 범위에 따라 기존 `tests/combat-status-browser.mjs`, `tests/identity-browser.mjs`, `tests/abilities-browser.mjs`와 저장·정비 관련 검사를 선택한다. 존재하는 테스트만 실행 결과로 기록한다.
- 720×1280 기준, 360×640 기본 모바일, 320 폭, 412 폭의 긴 화면에서 FIT·글자·터치·프레임 변형 확인.
- 보유 0/16·16/16, 출전 0/6·6/6, 긴 이름·다중 속성·큰 숫자·재료/재화 부족·최대 성장·대기 보상·저장/지급 실패 상태 확인.
- 조합 연타·직접 재료 선택·출전/각성 개체 소모·실패 무차감·페이지 이동 후 상태·보상 보류·정비 종료 확인.
- 전투 중 액티브+이동 동시 터치, 버튼 드래그 이탈, touch cancel, 모달 진입, blur·앱 복귀, 중첩 일시정지 확인.
- 보스 HP·페이즈·예고·문 열림, 웨이브 사이 적 0기, 부활·보호막, 재방문 보상 중복·재시작·이어하기 확인.
- 색만으로 적아·재료 부족·전투 불능을 구별하지 않아도 되는지 검토. 실제 최종 화면의 대비와 글자 축소 여부를 측정.
- 부하 비교는 같은 기기·브라우저·적/탄환 수·관찰 시간으로 기록. Android 노치·시스템 제스처·오프라인·앱 복귀는 실제 기기로 별도 확인.

### 이번 기획안 작업의 검증 범위

수정 MD를 읽고 PNG를 직접 확인했으며, 설명과 실제 소스의 차이를 대조했다. 신규 문서는 상대 링크·대상 경로·문자·코드 블록 구분자 등을 검사한다. 문서만 추가하므로 게임 테스트·빌드·새 목업 렌더링·Android 검증은 실행하지 않는다.

## 12. 다음 결과물과 결정 기록

다음 결과물은 첨부 PNG의 분위기와 이 문서의 실제 규칙을 결합한 **M1 타이틀, M2 정비, M3 전투, M4 재능/유물, M5 완료/최종 결과의 상세 목업**이다. P0 구현 검토는 전투 화면부터 진행한다.

상세 목업에서는 정상 상태와 함께 부족·비활성·전투 불능·선택 대기·저장 실패를 보여준다. 실행형 목업을 만들 경우 로컬 자산과 9:16 프레임을 사용하고, 모의 거래·가상 숫자를 실제 게임 기능과 구별해 표시한다.

결정 기록: [020 — 픽셀 판타지 디자인 방향 갱신](../../../../design/decisions/020-pixel-fantasy-design-proposal.md). 이전 019는 검토 이력으로 보존하며 새 상세 시안의 기준은 본 문서를 따른다.

### 후속 준비 단계 결과

사용자의 ‘다음단계 진행’ 요청으로 5화면과 주요 실패 상태를 확인하는 로컬 HTML 목업을 제작했다. 공통 패널·버튼·기존 아트·모의 상호작용을 포함하며, 설정은 검토용 스냅샷이고 게임 저장과 연결하지 않는다. 간편 제작·시설 등은 설명 진입점이며 전투는 정지 장면이다.

기존 테스트 148개·게임 빌드와 별도 Chrome 목업 검사 15개 배치를 통과했다. 브라우저 캡처 14개와 보고서를 남겼다. 상세 범위·실행 조건·한계는 위 사용법 문서를 따른다. 다음 구현 후보는 P0 전투 가독성이다.
