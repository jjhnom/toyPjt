# 소환사의 원정 — 상세 UI/UX 및 아트 디자인 명세 v2.0

> 대상 저장소: https://github.com/jjhnom/toyPjt/tree/main/rnd  
> 기준: `main/rnd`, 2026-11-09 확인. 시각적 참조: 사용자가 제공한 탕탕 에이스 플레이 영상과 이 대화에서 생성한 목업.  
> 이 문서는 **제안 명세**다. 이미 구현되었다는 뜻이 아니며, 원작 게임의 에셋과 규칙은 복제하지 않는다.

## 0. 목표와 변경 금지 원칙

- 핵심 게임 루프 **방 전투 → 재화 획득 → 동료 지정 소환 → 레시피 조합 → 출전 편성 → 다음 방 진행**을 변경하지 않는다.
- `SquadScene`이 전투 후 정비의 중심이라는 현행 계약을 유지한다. `RewardScene`을 주 보상 흐름으로 복구하지 않는다.
- 신규 랜덤 스킬 카드 선택, 전투 중 스킬 강화, 랜덤 가챠, 메타 성장 등은 이번 UI 리디자인 범위 밖이다. 목업의 '스킬 선택'은 향후 확장 컨셉이며 실제 구현에서는 기존 정비/유닛정보 패널로 치환한다.
- `GAME_WIDTH`, `GAME_HEIGHT`, `ARENA_BOUNDS`, 출전/보유 한도, 재화 규칙, 전투 데이터는 코드의 기존 값을 사용한다. 본 문서의 720×1280 좌표는 **현재 장면 코드에서 사용되는 기준 해상도에 대한 디자인 좌표**이며, 적용 전 `gameData.ts`와 실제 실행 화면에서 검증한다.
- 픽셀 아트 렌더링 유지: Phaser `pixelArt: true`, `roundPixels: true`, `Scale.FIT`.

## 1. 시각 컨셉

### 1.1 키워드

**Moonlit Arcane Fantasy** — 보랏빛 밤하늘, 고대 성과 던전, 반짝이는 마력석, 따뜻한 금색 액센트, 작지만 명확한 픽셀 캐릭터.

### 1.3 타이포

- 제목: 한국어 판타지 디스플레이 또는 굵은 고딕, 28~36px, 짙은 그림자/외곽선 사용.
- 화면 헤더: 24~30px, 금색 또는 크림색.
- 카드 타이틀: 20~24px, 숫자 정보 18~22px.
- 설명: 15~18px 이상. 핵심 정보는 최소 16px.
- 숫자 피해: 크기 22~36px. 치명타는 노랑/주황, 회복은 초록, 일반 피해는 밝은 아이보리.
- Android 가독성 고려: `Malgun Gothic` 및 시스템 sans-serif fallback. 중요한 수치는 stroke 또는 어두운 반투명 배경으로 대비 확보.

### 1.4 아트 규칙

- 유닛/적은 32×32 또는 48×48 기준 픽셀 원본을 nearest-neighbor 확대한다. 중요한 캐릭터 표시는 64×64~96×96의 시각적 영역 안에서 사용.
- 게임 캐릭터에 매끈한 AI 일러스트 스케일링을 직접 혼합하지 않는다. 메인 배경은 일러스트로 쓰더라도 캐릭터/아이콘은 픽셀 밀도를 통일한다.
- 캐릭터 정체성: 직업별 실루엣(검/활/지팡이/방패), 속성별 주색, 머리·무기 강조, 아군 푸른 윤곽/적군 붉은 윤곽.
- 효과 레이어: 바닥 텔레그래프 < 유닛 < 타격 < 피해 숫자 < HUD < 모달. UI 텍스트 가독성을 해치지 않도록 발광 강도를 제한.

## 2. 모바일 레이아웃 공통

### 2.1 720×1280 디자인 기준

- 안전 여백: 좌우 24px, 상단 24px, 하단 32px (+ 기기 안전 영역 별도).
- 세로 정보 계층: **상단 0~175px 정보**, **중앙 175~1040px 게임/카드**, **하단 1040~1280px 조작**. 실제 전투 아레나 bounds를 우선한다.
- 주요 버튼 높이 60~72px, 보조 48~56px, 터치 타깃 48×48px 이상.
- 탭 높이 54~64px; 선택 탭은 보라색 발광 + 금색 하단 바. 비활성은 회색 보라.
- 텍스트/시각적 꾸밈이 클릭 영역을 가리지 않도록, 인터랙티브 영역과 장식 레이어 분리.

### 2.2 핵심 UI 컴포넌트

### 2.3 접근성 및 성능

- 아이콘만으로 상태를 전달하지 말고 짧은 문구 또는 수치를 병기한다.
- 터치 후 100ms 이내 상태 변화, 긴 거래 작업에 중복 입력 방지. `SquadScene.transact`의 입력 잠금 유지.
- 애니메이션 감쇄 옵션 제안: 화면 흔들림과 큰 플래시를 최소화하고 모션 길이를 줄인다.
- 렌더 리소스가 많은 효과에는 풀링, 낮은 파티클 밀도 옵션, `update`당 신규 Graphics 과다 생성 금지.

## 3. 화면별 상세 명세

### 3.1 로비 — `MenuScene.ts`

**목표:** 세계관 소개와 새 모험/이어하기를 1초 이내 이해할 수 있게 한다.

1. 상단 80~270px: 로고/달빛 성/보라 마력석. 로고 최대 너비 540px.
2. 중앙 330~820px: 픽셀 소환사 캐릭터(시각 중심 360,660), 작은 동료 1마리. 강한 발광은 무기 끝에 한정.
3. 주요 CTA 880~970px: **새 모험 시작**, 저장 데이터가 있을 경우 **이어하기**를 동등한 위계로 노출. 실제 저장 정책과 연동.
4. 하단 1060~1220px: 설정/도움말 등 **실제 지원되는 메뉴만** 노출. 현재 기능이 없는 상점·도감·업적 등을 동작하는 것처럼 그리지 않는다.
5. 백그라운드: 느린 별빛(4~6초), 구름(12~18초), 캐릭터 idle(0.5~1.0초 순환).

**검수:** 중요한 버튼 48px 이상, 단말기 길이에 따라 로고/CTA가 겹치지 않음, 새 모험 데이터 교체 확인 UI 유지.

### 3.2 소환 — `SquadScene.ts`의 summon 탭

**목표:** 지정 소환 상품과 비용·현재 재화를 비교하기 쉽게 한다.

- 상단 24~190px: 화면 제목/스테이지 메시지/마력석/보유 N·한도/출전 N·한도.
- 탭 198~266px: **동료 소환 / 조합의 제단 / 원정대**를 유지. 간편 제작 플로우도 보존.
- 콘텐츠 282~1010px: 현재 `SUMMON_OFFERS`의 카드 목록을 기준으로 세로 스크롤/페이지네이션. 카드는 각 132~150px 높이.
- 카드 좌측: 초상화 84×84, 티어 금/보라/청색 테두리. 우측: 이름, 역할, 속성, 실제 `UNIT_SKILL_DESCRIPTIONS` 요약, 가격 버튼.
- 하단 1080~1208px: 선택/나가기 또는 상황별 CTA. `onClose` 콜백 및 원래 정비 흐름 유지.
- 소환 성공: 보석 소용돌이(0~220ms) → 캐릭터 중앙 등장(220~470ms) → 티어별 짧은 별 반짝임(470~700ms). 실제 게임 상태 갱신 이후 연출.
- 실패: 비용 부족/보유 한도/출전 한도를 명확하게 토스트로 표기. 중복 소환 방지.

### 3.3 조합 — `SquadScene.ts` combine 탭

**목표:** 무엇을 조합할 수 있고 어떤 재료가 부족한지 즉시 파악.

- 레시피 카드 너비 최대 648px; 상단에 결과 유닛/티어/속성, 중앙에 재료 개별 초상/보유 개수, 하단에 조합 CTA.
- 조합 가능: 금색 테두리/밝은 CTA, 조합 불가: 회보라 테두리/부족 재료 붉은 수치.
- 재료 직접 선택과 빠른 제작은 현행 `SquadRoster`의 기존 규칙/메서드를 사용한다.
- 상세 재료 선택 오버레이: 2~4열 초상 그리드, 선택 상태 굵은 금색 테두리+체크.
- 거래 후 레시피 소모 수량·결과 유닛과 상태를 즉시 갱신.

### 3.4 원정대 편성 — `SquadScene.ts` roster 탭

- 상단 현재 출전 카드: 출전 슬롯 한도를 `SQUAD_LIMITS.deployed`에서 읽어 동적으로 생성.
- 유닛 보유 그리드: `owned`, `deployed`, `dead`, `selected` 상태 분리. 유닛 상세: 이름, 속성, 역할, 티어/별, 체력, 스킬 설명.
- '출전/대기' 동작은 기존 분대 로직에 그대로 위임.
- 화면 모드별로 그리드를 조정하고, 픽셀 아트 카드의 촘촘한 프레임보다 데이터 가독성을 우선.
- 유닛 승급·판매는 기존 동작과 확정 문구를 유지. 위험한 거래에는 2차 확인.

### 3.5 전투 — `GameScene.ts`

**매우 중요한 제약:** 실제 게임에는 미니맵, 5개 분대 초상 HUD, 방향별 문, 가상 조이스틱, 하단 `소환의 서`, `중단 · 타이틀` 및 유닛 상세 팝업이 이미 구현되어 있다. 목업의 'Wave 5/10'과 하단 수동 스킬 5개 버튼은 참고 이미지용이며 현재 기능 계약이 아니다.

- 상단 10~152px: 기존 HP/스테이지/웨이브/마력석/분대 슬롯/미니맵. 프레임을 보라색으로 통일하되 **위치·클릭 이벤트는 유지**.
- 전투 아레나: `ARENA_BOUNDS` 내부 게임플레이 가시성 우선. 바닥은 저채도 보라 돌/이끼/문 형상. 강한 대비 요소를 적보다 덜 배치.
- 아군: 청색 외곽 픽셀 1~2px + 작은 상태 표시. 적: 몸체와 배경 대비 4.5:1에 준하는 시각 대비 목표.
- 적 소환: 먼지/마법진 200~400ms, 피격: 스파크 80~160ms, 처치: 조각/먼지 200~350ms.
- 중간/보스: 체력 강조바와 600~900ms 공격 사전 예고를 적용 가능한 기존 패턴에만 사용. 실제 판정/타이밍은 변경 금지.
- 하단 전투 조작: 기존 `VirtualJoystick` 작동 영역, 하단 메뉴를 가리지 않는다. 장식 효과가 이벤트를 가로채지 않아야 한다.
- 피해 숫자: 일반 크림, 치명타 주황/금색(치명타 판정이 실제로 있는 경우에만), 회복 초록. 스킬별 속성색 사용 가능.
- 성능: 한 프레임의 스킬 발광 영역이 넓어도 핵심 유닛/적 실루엣을 가리지 않도록, 최대 알파 0.65를 기본으로 한다.

### 3.6 정비/선택 패널

- 사용자가 고른 동료/조합 카드 중심의 모달로 설계. 참고 이미지의 '스킬 선택' UI를 그대로 기능화하지 않는다.
- `SquadScene`을 메인 정비 화면으로 유지하면서, 필요하면 유닛 상세 팝업에 3개 카드 시각 패턴만 재사용.
- 카드: 아이콘 64~88px, 제목 20~24px, 설명 최대 3줄, 등급별 테두리. 버튼은 선택 가능 상태에만 활성화.
- 닫기/뒤로/확인은 `onClose` 계약 유지.

### 3.7 결과 — `GameOverScene.ts` 및 현행 결과 흐름

- 상단 130~370px: 승리(금+보라 광선) / 패배(차분한 청회/붉은 톤) 변형.
- 중앙: 실제 계산되는 보상/방 클리어·처치 기록/출전 유닛 상태만 표시. 데이터를 임의 생성하지 않는다.
- 하단: **다음 스테이지 또는 타이틀 등 실제 분기만 노출**. 결과 처리/저장 정책 유지.
- 모션: 승리 배너 400ms 스케일/페이드, 보상 순차 강조 100ms 간격. 종료 애니메이션 총 1200ms 이내.

## 4. 시각 효과(VFX) 상세
