# 소환사의 원정 — 보스 몬스터 및 스킬 이미지 적용 가이드

**버전:** 1.0  
**기준 프로젝트:** `jjhnom/toyPjt/main/rnd`  
**게임 엔진:** Phaser 3 + TypeScript  
**논리 해상도:** 720 × 1280  
**목표:** 보스 5종의 고유 이미지와 스킬 이펙트를 실제 전투에 적용

---

## 1. 작업 목적

현재 구현된 보스 시스템의 게임 로직은 유지하면서, 앞서 제작한 보스 디자인 시안과 스킬 스프라이트를 실제 게임에 적용한다.

주요 목표:

1. 다섯 보스가 서로 다른 캐릭터 이미지로 등장한다.
2. 보스마다 속성에 맞는 스킬 이펙트를 사용한다.
3. 스킬은 경고 → 시전 → 발동 → 소멸로 연출한다.
4. 공격 범위와 실제 데미지 판정은 일치해야 한다.
5. 모바일 환경에서도 캐릭터와 스킬을 명확하게 식별할 수 있어야 한다.
6. 기존 공격 패턴, 데미지, HP, 이동, 보상 및 저장 로직은 변경하지 않는다.

## 4. 이미지 전처리 규칙

### 4.1 캐릭터 이미지

생성된 시트에서 다음 포즈를 분리한다.

- `idle`: 기본 대기 모습
- `cast`: 공격 에너지를 집중하는 모습
- `charge`: 공격하거나 돌진하는 모습

특정 포즈가 원본 시트에 명확하게 존재하지 않으면 임의의 잘못된 영역을 잘라내지 않는다. 기본 포즈와 Phaser의 이동·스케일 연출로 대체하거나 별도 아트를 제작한다.

권장 출력:

- 투명 배경 PNG
- 프레임마다 동일한 캔버스 크기
- 캐릭터 발 위치와 중심축 통일
- 원본 픽셀 형태를 보존하는 Nearest Neighbor 처리
- 원본 비율 유지

권장 게임용 프레임 크기는 초기 기준 128×128 또는 192×192이다. 실제 캐릭터가 잘리지 않는지 확인한 후 통일한다.

### 4.2 스킬 이미지

스킬 시트는 각 행이나 그림의 모양이 정확히 균일하지 않을 수 있으므로, 단순한 행·열 좌표 분할만으로 처리하지 않는다.

1. 개별 효과 경계를 검토한다.
2. 서로 겹친 광원과 배경 노이즈를 분리한다.
3. 투명 영역을 정리한다.
4. 동일 애니메이션의 프레임마다 중심축을 통일한다.
5. 일관된 캔버스 크기로 정규화한다.
6. 투명 가장자리와 잘림을 검수한다.

단순 검정색 제거는 어두운 보스 갑옷이나 그림자를 손상시킬 수 있으므로 주의한다.

### 4.3 권장 출력 규격

| 에셋 | 시작 규격 | 비고 |
|---|---|---|
| 보스 캐릭터 | 128×128~192×192 | 원본 비율과 발 위치 유지 |
| 작은 스킬 아이콘 | 64×64 | UI용 |
| 공격 경고 | 128×128 또는 256×256 | 실제 판정 크기에 따라 렌더링 |
| 타격 이펙트 | 128×128 | 투명 배경 |
| 대형 광역 이펙트 | 256×256 | 지나친 확대 방지 |
| 스프라이트 시트 | 동일 크기 프레임의 격자 | 프레임 수와 순서 명시 |

이 수치는 권장 시작값이며 현재 게임의 고정 사양은 아니다.

### 6.2 이미지 로딩

기존 Boot/Preload 구조에 보스 이미지를 등록한다.

```ts
this.load.image(
  'boss_forest_idle',
  'assets/bosses/forest_guardian/idle.png'
);
```

실제 경로가 Vite 정적 자산 경로와 일치하도록 조정한다.

5종 보스의 대기·시전·공격 이미지를 동일한 방식으로 등록한다.

### 6.3 Enemy.ts 수정

현재 보스는 `BOSS_CORE`를 기반으로 생성된다.

기존 스폰 및 물리 충돌 로직은 유지하고, `bossId`에 따라 텍스처를 변경하는 함수를 추가한다.

```ts
public applyBossProfile(id: BossId): void {
  this.bossId = id;

  const visual = BOSS_VISUALS[id];

  if (this.scene.textures.exists(visual.idle)) {
    this.anims.stop();
    this.setTexture(visual.idle);
    this.setTint(0xffffff);
  } else {
    this.setTint(visual.accent);
  }
}
```

주의사항:

- 보스 이미지 크기와 실제 충돌 크기를 분리한다.
- 기본 스프라이트 애니메이션이 신규 텍스처를 덮어쓰지 않게 한다.
- 피해를 받은 뒤 원래 텍스처와 색상을 복원한다.
- 보스 사망 시 남아 있는 연출을 정리한다.
- 보스 5종의 HP와 물리 판정은 기존 값 유지.

### 6.4 보스 스킬 이펙트 관리

`BossVfxController.ts`를 신규 생성하는 것을 권장한다.

역할:

- 공격 예고 텍스처 표시
- 공격 시전 연출
- 실제 타격 시 충격파 표시
- 지속 효과의 수명 관리
- 페이즈 전환 연출
- 보스 사망 시 이펙트 정리

기존 `EncounterHazards`는 게임 판정을 담당하고, `BossVfxController`는 시각적 표현만 담당하도록 한다.

권장 인터페이스:

```ts
type BossVfxEvent =
  | 'warning'
  | 'cast'
  | 'impact'
  | 'aftermath'
  | 'phaseChange'
  | 'defeated';
```

각 이벤트에는 보스 ID, 공격 종류, 좌표, 반경, 경고 시간, 지속 시간을 전달한다.

### 6.5 판정과 이펙트 동기화

공격 흐름:

1. `planBossAttack()`에서 공격 계획 생성
2. `EncounterHazards.add()`로 위험 영역 등록
3. VFX에 `warning` 이벤트 전달
4. 기존 경고 시간 동안 경고 이펙트 표시
5. 실제 판정 시 `impact` 이벤트 전달
6. 짧은 잔상 표시
7. 해당 공격 종료 시 이펙트 제거

새로운 타이머가 기존 공격보다 먼저 또는 늦게 데미지를 발생시키면 안 된다.

시각적 이펙트가 실패하거나 풀 상한에 도달하더라도 공격 판정은 정상적으로 실행되어야 한다.

## 7. 권장 시각적 연출 시간

| 구분 | 권장 시간 |
|---|---|
| 공격 예고 | 기존 `warningMs` 유지 |
| 시전 강조 | 경고 시간의 마지막 20~30% |
| 타격 섬광 | 80~120ms |
| 충격파 | 180~300ms |
| 파편 | 200~400ms |
| 잔상 | 300~600ms |
| 페이즈 전환 오라 | 500~900ms |

위 값은 시각적 제안이며 공격 판정 시간은 바꾸지 않는다.

## 8. 성능 및 모바일 최적화

- 텍스처는 로딩 시 등록하고 매 프레임 재생성하지 않는다.
- 반복 효과는 기존 `EffectParticlePool` 재사용을 우선한다.
- 모바일에서 과도한 반투명 레이어 중첩을 방지한다.
- 보스 이미지 확대 시 Nearest Neighbor 설정을 유지한다.
- 대형 폭발은 실제 위험 범위를 가리지 않도록 한다.
- 화면 흔들림은 짧게 적용하고 끌 수 있는 옵션을 고려한다.
- 일시정지 중에는 시각 애니메이션과 공격 판정이 함께 멈춰야 한다.
- 스테이지 전환 및 보스 사망 시 이펙트 참조를 해제한다.

## 11. Codex 최종 작업 지시

위 가이드와 함께 보스 디자인 시안 5개, 보스 캐릭터 스프라이트 시트 5개, 스킬 VFX 시트 5개를 참고해 주세요.

작업 시 다음 원칙을 반드시 준수합니다.

1. 먼저 이미지 파일의 프레임 구성을 분석한다.
2. 잘못된 자동 분할로 캐릭터가 잘리지 않도록 한다.
3. 실제로 적용 가능한 이미지인지 확인한 후 프로젝트에 연결한다.
4. 기존 보스·공격 로직을 변경하지 않는다.
5. 보스 이미지 변경과 공격 연출 변경을 별도 단계로 진행한다.
6. 스킬별로 변경 전후 화면을 비교한다.
7. 신규 기능이 필요한 경우 구현하지 말고 제안으로 분리한다.
8. 최종 변경 파일, 테스트 결과, 남은 문제를 한국어로 보고한다.
9. 요청받지 않은 Git push나 merge는 수행하지 않는다.

**최종 목표: 보스 5종이 실제 디자인 시안과 유사한 고유 외형과 스킬 이펙트를 갖추되, 기존 게임 로직과 성능을 유지하는 것이다.**
