# 적·탄환·VFX 부하 계측 — 2026-11-19

## 범위와 환경

사용자 요청에 따라 적 10/32/64기 × 탄환 40/100/160개를 계측했다. 여기에 서리 여왕 장판·연속 폭격을 겹친 32/100, 64/160 조건을 추가했다. 게임 코드·밸런스·풀 크기는 수정하지 않았다.

- Windows 10.0.26200, Intel Core i7-1260P, 논리 CPU 16개, RAM 약 31.7GiB.
- Headless Chrome 157.0.8103.79, WebGL, **ANGLE Vulkan SwiftShader 소프트웨어 렌더링**.
- 모바일 에뮬레이션 720×1280, DPR 1, 게임 해상도 720×1280. 실제 Android 측정이 아니다.
- Vite 개발 서버, 오디오 비활성화, 기본 출전 유닛 2기. 최종 편성·오디오 동시 부하를 대표하지 않는다.
- 계측 중 별도 테스트·빌드를 실행하지 않았다. 측정 종료 후 실행했다.

## 방법

각 조건은 1.2초 준비 후 약 5초 관찰했다. 11조건을 정순·역순으로 각 1회씩, 총 22회 측정했다. 최대 부하 조건 1회는 풀 준비용으로 먼저 실행하고 결과 표에서 제외했다. 브라우저 스위트 전체 실행은 153.929초였다.

모든 조건은 서리 여왕 1기와 나머지 TANK로 구성한다(적 목표 수에 보스 포함). 적·아군의 체력을 높이고 아군을 무적 처리해 개체 수와 런을 유지했다. 예약 스폰·자동 보스 패턴만 차단했으며 실제 AI·분대 사격·탄환 수명·적중·충돌·파티클·렌더링은 실행했다. 따라서 표의 기본 조건은 작업 문서의 '일반 적만 있는 전투'와 차이가 있다. VFX 유무 비교 시 보스 구성을 동일하게 유지하기 위한 합성 부하 장면이다.

탄환은 씬 `postupdate`에서 부족분을 기존 풀의 `fireBullet`로 보충하고 초과분을 비활성화했다. 표의 탄환 수는 이 시점의 목표값이며, 물리 처리 중 줄어드는 순간까지 해당 수를 보장하지 않는다. 보충 전 실제 개수도 원본 JSON에 별도로 기록했다. VFX 조건은 3.2초마다 실제 서리 여왕 10회 폭격 계획과 별도 FROST 장판 2개를 추가한다. 자연 플레이의 패턴 주기를 변경한 것이 아니다.

FPS는 RAF 타임스탬프 간격의 합으로 계산하고 p95는 정렬 후 nearest-rank 방식으로 구했다. `prestep`~`postrender` 시간은 물리·업데이트·렌더 제출을 포함하는 메인 스레드 경과 시간이다. GPU 완료 시간이나 순수 게임 로직 CPU 시간이 아니다. 계측과 탄환 보충의 오버헤드도 포함된다. 프레임 샘플은 사전 할당한 버퍼에 저장한다.

## 실측 결과

슬래시로 구분한 값은 1차 / 2차다. 파티클·보스 VFX는 두 관찰 구간에서의 최대 활성 수다.

| 적 | 탄환 목표 | 추가 보스 VFX | 평균 FPS | 프레임 p95(ms) | 메인 스레드 p95(ms) | 파티클 최대 | 보스 VFX 최대 |

| 10 | 40 | 없음 | 25.72 / 17.88 | 50.0 / 66.7 | 3.5 / 4.6 | 75 | 0 |
| 10 | 100 | 없음 | 20.99 / 17.88 | 50.1 / 66.7 | 4.6 / 5.0 | 100 | 0 |
| 10 | 160 | 없음 | 18.88 / 17.74 | 66.7 / 66.7 | 6.2 / 6.0 | 120 | 0 |
| 32 | 40 | 없음 | 20.86 / 18.08 | 50.1 / 66.7 | 4.3 / 5.2 | 74 | 0 |
| 32 | 100 | 없음 | 19.54 / 17.82 | 66.7 / 66.7 | 5.2 / 5.5 | 120 | 0 |
| 32 | 160 | 없음 | 18.94 / 16.97 | 66.7 / 66.7 | 5.5 / 7.2 | 120 | 0 |
| 64 | 40 | 없음 | 18.16 / 17.14 | 66.7 / 66.7 | 7.5 / 5.8 | 106 | 0 |
| 64 | 100 | 없음 | 17.68 / 18.48 | 66.8 / 66.7 | 8.2 / 5.3 | 120 | 0 |
| 64 | 160 | 없음 | 16.09 / 16.69 | 66.8 / 66.7 | 7.9 / 7.6 | 120 | 0 |

| 64 | 160 | 장판+폭격 | 13.42 / 13.77 | 83.4 / 83.4 | 8.9 / 8.1 | 120 | 12 |

- 모든 관찰 프레임의 적 수와 보충 후 탄환 수가 목표와 일치했다. 런타임 예외·VFX 실패는 없었다.
- 관찰 중 씬 자식 수는 22회 모두 615개였다. 파티클 상한 120개, 보스 VFX 상한 32개를 넘지 않았다. 높은 부하에서는 파티클 120개에 도달했다. 이때 생략된 이펙트 요청 수는 계측하지 않았다.
- 이 환경에서 60 FPS 목표를 달성하지 못했다. 특히 보스 VFX 중첩 조건은 기본 조건보다 낮은 FPS를 기록했다. 다만 10/40 조건도 반복 간 25.72 → 17.88 FPS로 달라져 시간 경과·환경 편차가 크다. 이를 정밀한 VFX 비용 비율이나 특정 코드의 병목 증거로 해석하지 않는다.
- 메인 스레드 p95와 전체 프레임 간격 사이에 큰 차이가 있다. 소프트웨어 렌더링·브라우저 스케줄링 등의 영향이 있을 수 있으나 이번 계측으로 원인을 분리하지는 못했다. 측정에 근거하지 않은 로직 최적화는 적용하지 않았다.

## 메모리와 종료 정리

최대 부하로 풀을 준비한 뒤와 22회 종료 뒤에 각각 CDP 강제 GC 후 `Runtime.getHeapUsage`를 읽었다.

| 항목 | 준비 후 | 종료 후 | 변화 |
|---|---:|---:|---:|
| JS used heap(bytes) | 14,623,720 | 15,537,640 | +913,920 (약 0.87MiB) |
| backing storage(bytes) | 55,852,170 | 55,852,185 | +15 |

종료 정리 후 적·탄환·파티클·보스 VFX·위험 영역의 활성 수와 계측용 씬 리스너 수는 모두 0이었다. 짧은 1회 실행의 힙 차이는 풀·캐시·JIT 및 계측 데이터의 영향을 포함할 수 있다. JS 힙 수치는 프로세스 전체·GPU·네이티브 메모리가 아니며 메모리 누수 여부를 판정할 근거로 충분하지 않다.
