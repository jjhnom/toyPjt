# 통합 안정화 1차 — 자동 회귀와 클래스 비교

2026-11-07 STABILIZE-001A 완료. 0~12단계 MVP의 자동 검증을 묶고 검사 도구의 새로고침 연결 경합을 보강했다. 게임 수치·규칙·출시 설정은 변경하지 않았다. 사람 플레이와 Android 실기기 QA는 STABILIZE-001B로 남는다.

## 실행과 결과

개발 서버를 `npm run dev`로 실행한 상태에서 프로젝트 루트의 다른 터미널에서 실행한다.

```powershell
npm test
npm run build
npm run test:integration
```

`SMASH_TEST_URL`로 개발 서버 주소, `SMASH_BROWSER_PATH`로 Chrome 실행 경로를 지정할 수 있다. 기본 주소는 `http://127.0.0.1:5173/`, 기본 Chrome은 Windows 설치 경로다. 소스 모듈을 가져오는 검사이므로 Vite 개발 서버가 필요하다. 검사 도구는 기존 서버를 종료하거나 변경하지 않는다.

특정 검사는 `npm run test:integration -- legacy-browser class-balance-browser`, 클래스 비교만 실행하려면 `npm run balance:classes`를 사용한다. 각 검사는 별도 Chrome 프로필을 사용하고 순차 실행한다. 실패하면 해당 지점에서 종료 코드1로 멈추고 후속 검사를 실행하지 않는다. 자동 재시도는 하지 않는다. `artifacts/integration/report.json`에 URL·Node 버전·실행 검사·상태·소요 시간·로그 경로를 기록하며 다음 실행에서 최신 결과로 교체한다.

| 검사 | 최종 결과 | 범위 |
| --- | --- | --- |
| `npm test` | 148개 통과 | 거래·성장·전투·저장 모델 |
| `npm run build` | 통과 | strict TypeScript·Vite, 기존500kB 번들 경고 유지 |
| `browser-smoke` | 통과 | 기존 소환/조합·입력·룸·종료·저장 흐름 |
| `checkpoint-v2-browser` | 통과 | 거래 중단·부활 시간·소환진/샘·중간 보스·백업·사망 |
| `abilities-browser` | 통과 | 재능·치유·취소/동시 터치·정지·무한 변이 |
| `facilities-browser` | 통과 | 각성·소멸 확인·회복/부활·보급·실패 복원 |

| `class-balance-browser` | 통과 | 실제 탄환24조건·회복/정화6조건·연속 새로고침3회 |

환경은 Windows, Node22.16.0, Chrome156.0.8078.80이다. 기존 UI 검사는720/360 세로 뷰포트의 브라우저 터치 에뮬레이션이다. 최종 통합 실행은 8종 모두 통과했다. 보고서는 `artifacts/integration/report.json`, 검사별 로그는 같은 디렉터리, 클래스 상세는 `artifacts/class-balance/report.json`에 있다. 실제 Android WebView·기기의 성능 검증을 대신하지 않는다.

## 클래스 비교

Lv.1 영웅과 고정된 고체력 표적, 60Hz의20초 모의 전투다. 아군 무기·적 공격·레벨업을 제외하고 모든 클래스에 같은 좌표를 사용했다. 영구 HP/공격0단계와 각각5단계를 비교했다. 아래 DPS는 이 유한한 관측 구간에 실제 적 HP에서 차감한 피해/20초이며, 마지막 비행 중 탄환의 미도착 등도 포함한다. 무한 시간 명목 DPS가 아니다.

| 클래스·영구 단계 | 최대 HP | 단일 DPS | 밀집4 DPS | 분산4 DPS | 거리200 DPS |
| --- | --- | --- | --- | --- | --- |
| 견습·0/0 | 100 | 7.20 | 7.20 | 7.20 | 7.20 |
| 기사·0/0 | 125 | 8.00 | 8.00 | 8.00 | 0 |
| 술사·0/0 | 90 | 6.75 | 20.25 | 6.75 | 6.75 |
| 견습·5/5 | 125 | 11.70 | 11.70 | 11.70 | 11.70 |
| 기사·5/5 | 150 | 12.00 | 12.00 | 12.00 | 0 |
| 술사·5/5 | 115 | 10.50 | 30.75 | 10.50 | 10.50 |

회복은 HP1의 본체와 시작 사수2기에서 한 번 시전했다. 견습은 본체10/동료각10, 기사는 본체25/동료0, 술사는 본체6/동료각6이었다. 모두18초 대기와 즉시 재시전 차단을 확인했다. 전원 만피+유효 감속 조건에서는 술사만 정화하며 대기를 소비했다. 실제 표적 HP 차감과 피해 계측의 일치·풀 실패0·레벨 유지·단일 공격의 무료 범위 피해 없음도 검사했다.

현재 조건에서는 기사의 근거리 단일·본체 회복, 술사의 밀집 범위·정화, 견습의 팀 회복 차이가 나타났다. 전투 중 접근 위험·적 분산/AI·분대 기여·전체 런 생존은 이 비교에 포함하지 않았으므로 수치 조정 근거로 단독 사용하지 않는다. 이번에는 현재 수치를 유지한다.

## 검사 도구 보강과 한계

기존 `Page.reload` 호출은 문서 전환이 커밋되기 전에 응답할 수 있는데, `attach`는 캔버스부터 검사해 이전 문서의 게임에 연결할 수 있었다. 이제 CDP의 최상위 문서 loader 변경을 확인하고 새 문서의 메뉴까지 대기한다. 연결 중 예상치 못한 문서 변경은 실패로 처리한다. 연속 새로고침3회에서 이전 전역 표식 소멸·캔버스1개를 확인했고 기존 재접속 검사 전체를 다시 통과했다.

초기 검사에서는 캔버스/메뉴 대기 실패와 이미지/모듈의 미완료·중단 요청, 일부 `ERR_NETWORK_CHANGED`를 관측했다. 완료된 요청을 추적 목록에서 지우고 실패 시 미완료 URL을 출력하도록 보강했다. 별도 서버를 내부에서 만드는 시도 대신 응답이 확인된 기존 개발 서버를 사용하는 실행 경로로 정리했다. 최종 검사는 통과했지만 모든 초기 네트워크 정체의 원인이 해결됐다고 단정하지 않는다. 실제 플레이의 시작/재접속 결함이 확인된 것으로 보고하지 않는다.

## 남은 사람 플레이·Android QA
